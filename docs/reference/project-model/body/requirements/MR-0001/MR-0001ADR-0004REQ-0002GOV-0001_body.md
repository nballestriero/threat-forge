# MR-0001ADR-0004REQ-0002GOV-0001 — Provenienza canonica obbligatoria e divieto di duplicazione

## Intento

Impedire che tool, schema, task, API o componenti frontend mantengano copie locali divergenti dei valori controllati, degli alias o dei metadati di presentazione.

## Obbligo di governance

Ogni input o output controllato deve dichiarare la fonte canonica da cui derivano valori, significati, label, selezionabilita, alias e metadati di presentazione.

E vietato introdurre in codice operativo:

- enum locali di valori controllati;
- alias non dichiarati dalla fonte canonica;
- significati o descrizioni sostitutive;
- colori con significato di dominio duplicato;
- regole di applicabilita ricostruite indipendentemente dal catalogo;
- conversioni che trasformano un valore astratto o vietato in un valore concreto accettabile.

Sono ammessi valori non validi soltanto in fixture negative isolate e chiaramente identificate come casi di errore.

## Controlli minimi

I controlli devono verificare almeno:

- che ogni campo controllato consumato da un artefatto dichiari la propria fonte;
- che ogni valore operativo provenga dal catalogo o dalla fonte canonica dichiarata;
- che gli alias accettati siano registrati esplicitamente;
- che valori astratti, vietati o non memorizzabili vengano respinti prima di qualsiasi scrittura;
- che schema, cataloghi derivati, API e frontend non ridefiniscano descrizioni o valori;
- che il body Markdown non venga trattato come fonte autonoma dei campi strutturati.

## Failure mode

Il controllo deve fallire quando trova una lista operativa hardcoded, un alias implicito, una descrizione duplicata, una fonte mancante o una trasformazione che nasconde un valore vietato convertendolo in un valore valido.
