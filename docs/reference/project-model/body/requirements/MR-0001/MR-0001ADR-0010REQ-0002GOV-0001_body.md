# MR-0001ADR-0010REQ-0002GOV-0001 — Deterministic governed document model consumer provider coverage

## Intent

Make consumer-local canonical model inventories, fixed model cardinalities and
incomplete model-provider catalogs deterministically detectable before a new
governed document model is activated.

## Governance obligation

- ThreatForge must provide one shared side-effect-free validator for governed document model consumer coverage.
- The coverage validator must consume canonical model identifiers derived from the canonical document model index.
- The coverage validator must consume one explicit consumer identifier and the model identifiers supported by that consumer.
- The coverage validator must emit stable diagnostic rule identifiers.
- The coverage validator must report duplicate provider model identifiers.
- The coverage validator must report every canonical model without a consumer provider.
- The coverage validator must report every consumer provider whose model identifier is absent from the canonical index.
- Coverage diagnostics must be deterministic and sorted independently of provider input order.
- Coverage validation must not mutate the canonical source set or the supplied provider inventory.
- Governed Markdown assistance, governed authoring contract verification and Target Project validation must use the shared coverage boundary.
- Source-loader verification must prove that canonical model and profile cardinalities are extensible.

## Verification obligations

- The verification must confirm exact provider coverage for the current canonical model inventory.
- The verification must confirm that a coherent synthetic additional model and its referenced profiles are accepted without changing fixed-count code.
- The verification must detect one missing canonical model provider.
- The verification must detect one unregistered provider model identifier.
- The verification must detect duplicate provider identifiers.
- The verification must prove deterministic diagnostic ordering.
- The verification must prove that input source sets and provider arrays remain unchanged.
- The verification must confirm that current Markdown assistance, authoring and Target Project checks continue to cover all active canonical models.

## Failure conditions

- The verification must fail when a consumer compares against a locally authored canonical model list.
- The verification must fail when a consumer assumes a fixed canonical model or profile count.
- The verification must fail when an active canonical model has no required consumer provider.
- The verification must fail when a provider targets a model absent from the canonical index.
- The verification must fail when a provider model identifier is duplicated.
- The verification must fail when requirement registry dispatch accepts only locally hard-coded requirement types.
- The verification must fail when diagnostics are unstable across equivalent provider orderings.
- The verification must fail when validation mutates canonical source data or provider input.
