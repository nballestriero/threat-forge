# MR-0001ADR-0006REQ-0001 — Generatore locale di handoff archive

## Intent

Produce a governed local handoff archive that allows another development session or LLM to reconstruct the current ThreatForge repository context.

## Functional obligation

- ThreatForge must provide a local command that generates a ZIP handoff archive under `artifacts/handoff/`.
- The handoff generator must capture the current Git state and recent commits.
- The handoff generator must capture the current ThreatForge repository-check result.
- The handoff generator must include relevant governed registry snapshots and continuation instructions.
- The handoff generator must include a snapshot of files tracked by Git under `project-snapshot/`.
- The handoff generator must include a manifest describing file counts and inclusion or exclusion rules.
- The handoff generator must support a read-only `--dry-run` mode.
- The handoff generator must not mutate governed repository content while producing the archive.

## Scope

- Includes: local ZIP generation
- Includes: human-readable handoff documents and logs
- Includes: tracked project files
- Includes: snapshot manifest and continuation prompt
- Excludes: `.git`, installed dependencies, caches and build outputs
- Excludes: untracked repository artifacts
- Excludes: GitHub release creation and remote archive upload

## Acceptance

- The requirement is accepted when one local command produces a readable ThreatForge handoff ZIP.
- The requirement is accepted when the archive contains both operational context and the tracked project snapshot.
- The requirement is accepted when the manifest states the snapshot file count and filtering rules.
- The requirement is accepted when `--dry-run` reports the planned archive without writing it.
- The requirement is accepted when the generated archive tool is represented in the implementation trace registry.
