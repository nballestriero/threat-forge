# MR-0001ADR-0010REQ-0001GOV-0001 — Governed activation of document model extensions

## Intent

Establish the evidence and consistency conditions that distinguish a registered document model extension from an active and consumable governed model.

## Governance obligation

- ThreatForge must treat a document model extension as active only after its canonical sources and declared coverage are complete.
- Every active model entry must use a stable unique model identifier.
- Every active model entry must resolve exactly one registry representation profile.
- Every active model entry must resolve exactly one Markdown body representation profile.
- Every active model extension must declare its model validation coverage.
- Every active model extension must declare its required consumer coverage.
- Deterministic consumer projections must be regenerated from the canonical model sources before activation.
- A document model extension must not depend on filesystem discovery.
- A document model extension must not depend on a consumer-local canonical inventory.

## Verification obligations

- The verification must confirm that every active model resolves its declared representation profiles.
- The verification must confirm that active model and profile identifiers are unique.
- The verification must confirm that declared model validation coverage exists.
- The verification must confirm that every declared consumer recognizes the active model inventory.
- The verification must confirm that deterministic generated outputs match the canonical model sources.
- The verification must reject incomplete or inconsistent model activation.

## Failure conditions

- The verification must fail when an active model references an unresolved registry representation profile.
- The verification must fail when an active model references an unresolved Markdown body representation profile.
- The verification must fail when an active model identifier is duplicated.
- The verification must fail when a representation profile identifier is duplicated.
- The verification must fail when declared model validation coverage is missing.
- The verification must fail when declared consumer coverage is incomplete.
- The verification must fail when a deterministic consumer projection is stale.
- The verification must fail when model availability depends on filesystem discovery.
- The verification must fail when a consumer maintains an independent canonical model inventory.
