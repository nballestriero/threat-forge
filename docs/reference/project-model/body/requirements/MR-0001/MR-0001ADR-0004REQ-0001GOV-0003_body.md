# MR-0001ADR-0004REQ-0001GOV-0003 — Concretezza e regole dei tipi di requisito

## Intento

Impedire che una categoria astratta venga memorizzata come tipo concreto e rendere derivabili le regole di parentela applicabili a ogni requisito governato.

## Obbligo di governance

Il registro dei valori controllati deve definire un value set contestuale denominato `requirement_type` per il campo omonimo dei registri dei requisiti.

Ogni valore del value set deve rappresentare un tipo concreto e deve dichiarare almeno:

- `value`;
- `meaning`;
- `is_specialized`;
- `requires_parent_requirement`;
- `allowed_parent_requirement_types`.

`specialized` e una categoria astratta e non deve comparire tra i valori ammessi di `requirement_type`.

L'insieme iniziale deve definire:

- `functional`, non specializzato, senza requisito padre;
- `governance`, specializzato, con requisito padre obbligatorio di tipo `functional`.

Ogni estensione deve introdurre un tipo concreto distinto, con significato e regole applicabili esplicite. Un tipo concreto non deve essere introdotto come alias implicito di un altro tipo.

## Controlli minimi

Il controllo deve verificare almeno:

- presenza del value set `requirement_type`;
- unicita dei tipi concreti;
- assenza del valore `specialized`;
- presenza e tipo booleano di `is_specialized` e `requires_parent_requirement`;
- presenza di `allowed_parent_requirement_types`;
- lista dei tipi padre vuota quando il padre non e richiesto;
- lista dei tipi padre non vuota e composta da tipi concreti registrati quando il padre e richiesto;
- uso nei registri dei requisiti di soli tipi concreti registrati;
- presenza o assenza di `parent_requirement_id` coerente con le regole del tipo concreto;
- tipo del requisito padre compreso tra quelli ammessi.

## Failure mode

La verifica deve fallire in presenza di categorie astratte usate come tipi, tipi non registrati, metadati di regola mancanti, relazioni padre vietate o obbligatorie ma assenti, oppure tipi padre non ammessi.
