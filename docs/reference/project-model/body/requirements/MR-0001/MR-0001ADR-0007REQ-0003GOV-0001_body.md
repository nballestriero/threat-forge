# MR-0001ADR-0007REQ-0003GOV-0001 — Gate activation only after complete migration

## Intent

Keep the governed branch usable while new document rules are implemented and the active corpus is migrated.

## Governance obligation

- New document model checks must remain non-blocking while the active corpus contains known migration findings.
- Migration changes must be divided by complete logical document category.
- Every migration increment must leave all previously active repository checks passing.
- New model checks must become active only after the complete migration report contains zero errors.
- ThreatForge must not introduce permanent exceptions for pre-profile document formats.

## Verification obligations

- The verification must execute the existing active repository gate after every migration increment.
- The verification must execute all model validators against the complete active corpus before activation.
- The verification must confirm that no active record or referenced body remains unclassified.
- The verification must confirm that retired partial checks have replacement coverage.

## Failure conditions

- The verification must fail when a blocking model check is activated before migration reaches zero errors.
- The verification must fail when a migration increment breaks a previously active repository check.
- The verification must fail when an active document is excluded through an ungoverned exception.
- The verification must fail when a legacy compatibility mode remains enabled after activation.
