# MR-0001ADR-0007REQ-0001 — Canonical profiles for governed document models

## Intent

Make the complete structure and semantics of each governed document type explicit and machine-readable.

## Functional obligation

- ThreatForge must define one canonical logical model for Macro-requirements.
- ThreatForge must define one canonical logical model for Decisions.
- ThreatForge must define one canonical logical model for Functional Requirements.
- ThreatForge must define one canonical logical model for Governance Requirements.
- Each logical model must reference its applicable YAML registry profile.
- Each logical model must reference its applicable Markdown body profile.
- ThreatForge must define stable identifiers for every governed field and section.
- ThreatForge must reference controlled value sets instead of duplicating their values inside document profiles.

## Scope

- Includes: Macro-requirement registry records and bodies
- Includes: Decision registry records and ADR bodies
- Includes: Functional Requirement registry records and bodies
- Includes: Governance Requirement registry records and bodies
- Excludes: ordinary tutorial, how-to, reference and explanation documents

## Acceptance

- The requirement is accepted when four logical model definitions are present.
- The requirement is accepted when seven representation profiles are present.
- The requirement is accepted when every profile declares canonical order, cardinality and content semantics.
- The requirement is accepted when controlled fields reference existing canonical value sets.
