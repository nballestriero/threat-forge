# MR-0001ADR-0007REQ-0001 — Canonical profiles for governed document models

## Intent

Make the complete structure and semantics of each governed document type explicit and machine-readable.

## Functional obligation

- ThreatForge must define one canonical logical model for every active model entry in the canonical document model index.
- Each active logical model must reference exactly one applicable YAML registry profile.
- Each active logical model must reference exactly one applicable Markdown body profile.
- The active representation-profile inventory must be derived from the profiles referenced by active model entries.
- ThreatForge must define stable identifiers for every governed field and section.
- ThreatForge must reference controlled value sets instead of duplicating their values inside document profiles.

## Scope

- Includes: logical models registered in the canonical document model index
- Includes: YAML registry profiles referenced by active model entries
- Includes: Markdown body profiles referenced by active model entries
- Includes: canonical field and section semantics for active governed document models
- Excludes: ordinary tutorial, how-to, reference and explanation documents

## Acceptance

- The requirement is accepted when every active model entry resolves exactly one canonical logical model definition.
- The requirement is accepted when every active model resolves exactly one registry profile and one Markdown body profile.
- The requirement is accepted when every profile declares canonical order, cardinality and content semantics.
- The requirement is accepted when controlled fields reference existing canonical value sets.
