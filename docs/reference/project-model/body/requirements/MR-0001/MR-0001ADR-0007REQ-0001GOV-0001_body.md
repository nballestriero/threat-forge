# MR-0001ADR-0007REQ-0001GOV-0001 — Single source and deterministic profile validation

## Intent

Prevent model definitions, editor projections and checks from becoming competing sources of document rules.

## Governance obligation

- Canonical document profiles must be stored under the governed project model.
- A consumer must not maintain an independent inventory of canonical fields or sections.
- A document profile must reference canonical controlled value sets by stable identifier.
- Profile validation must reject unknown fields, sections, value sets and model references.

## Verification obligations

- The verification must validate every document profile against its governed schema.
- The verification must report duplicate model, representation, field and section identifiers.
- The verification must confirm that every referenced controlled value set exists.
- The verification must confirm that section and field order is deterministic.
- The verification must compare generated projections with their canonical profiles.

## Failure conditions

- The verification must fail when two profiles declare the same canonical identifier.
- The verification must fail when a profile duplicates values owned by a controlled value set.
- The verification must fail when a required representation is absent from a logical model.
- The verification must fail when a generated projection diverges from its canonical profile.
