# MR-0001REQ-0021GOV-0001 — Code traceability negative fixture coverage

## Intent

The bidirectional code traceability checker must prove that it fails closed for representative invalid graph/source-code states, not only that it passes the current repository state.

Negative fixtures make the checker's failure behavior deterministic and protect future changes from weakening graph-to-code or code-to-graph enforcement.

## Parent Functional Requirement

Parent functional requirement: `MR-0001REQ-0021` — Bidirectional graph-to-code traceability validation.

This specialized governance requirement hardens the functional bidirectional validator by requiring fixture-backed evidence for invalid traceability states.

## Specialized Requirement

The code traceability gate must execute deterministic negative fixtures that model broken graph/code traceability cases and must fail if any fixture unexpectedly passes or emits the wrong diagnostic.

The negative fixtures must exercise the same validation logic used by the real repository check rather than relying only on separate hand-written assertions.

## Scope

This requirement applies to the `docs:code-traceability` gate and its code traceability validator.

It covers representative negative cases for missing source JSDoc declarations, missing graph implementation relations, unknown requirement declarations, and graph code artifact paths that do not exist.

It does not require a full external test framework, full repository cloning, mutation of the live repository, fixture coverage for every future traceability rule, or validation of non-code artifacts outside the existing code traceability scope.

## Rules

- The code traceability validator must discover negative fixture records from a deterministic repository path.
- Each negative fixture must be self-contained and must describe the minimal project-model and source files required for that fixture.
- Each negative fixture must be executed in an isolated temporary repository tree.
- The fixture run must use the same checker implementation as the real repository gate.
- A fixture must pass only when the checker exits non-zero for the invalid state and emits the expected diagnostic fragment.
- The real repository check must fail if a negative fixture unexpectedly passes.
- The real repository check must fail if a negative fixture fails for a diagnostic unrelated to the expected invalid state.
- The validator must avoid recursively running negative fixtures inside fixture executions.
- The implementation must include JSDoc traceability to this requirement.

## Acceptance Criteria

```gherkin
Scenario: Graph implementation relation without source marker is rejected
  Given a fixture graph declares a Requirement implemented_by Tool relation
  And the referenced source file does not declare the implemented Requirement
  When the code traceability gate runs the negative fixtures
  Then the fixture run fails with a graph-to-code diagnostic

Scenario: Source marker without graph implementation relation is rejected
  Given a fixture source file declares @implementsRequirement for a known Requirement
  And the fixture graph has no matching implemented_by relation for that source path
  When the code traceability gate runs the negative fixtures
  Then the fixture run fails with a code-to-graph diagnostic

Scenario: Unknown source requirement declaration is rejected
  Given a fixture source file declares @implementsRequirement for an unknown Requirement id
  When the code traceability gate runs the negative fixtures
  Then the fixture run fails with an unknown Requirement diagnostic

Scenario: Missing code artifact path is rejected
  Given a fixture graph relation points to a Tool node with a missing source path
  When the code traceability gate runs the negative fixtures
  Then the fixture run fails with a missing path diagnostic
```

## Verification Expectation

Running `npm run docs:code-traceability` must report the number of negative fixtures executed and must fail if any fixture no longer proves the expected invalid graph/code traceability behavior.
