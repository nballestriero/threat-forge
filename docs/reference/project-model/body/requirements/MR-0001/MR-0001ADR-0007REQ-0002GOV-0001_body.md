# MR-0001ADR-0007REQ-0002GOV-0001 — Stable rule identifiers and model-organized fixtures

## Intent

Make every validation rule independently identifiable, testable and reusable by repository and editor consumers.

## Governance obligation

- Every governed document rule must have a stable canonical identifier.
- A rule identifier must identify its logical model, representation and governed concern.
- Negative fixtures must be organized by logical model and rule concern.
- A negative fixture must declare the rule identifiers it expects to trigger.
- Diagnostic messages must not be used as substitutes for stable rule identifiers.

## Verification obligations

- The verification must confirm that every emitted diagnostic declares a known rule identifier.
- The verification must confirm that every negative fixture triggers its declared rule identifiers.
- The verification must confirm that fixture directories map to known logical models.
- The verification must reject duplicate rule identifiers.

## Failure conditions

- The verification must fail when a diagnostic omits its rule identifier.
- The verification must fail when a fixture succeeds without triggering its expected rule.
- The verification must fail when two rules use the same identifier.
- The verification must fail when a fixture is stored outside its model-specific structure.
