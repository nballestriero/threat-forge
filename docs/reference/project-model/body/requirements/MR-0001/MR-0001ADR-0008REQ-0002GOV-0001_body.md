# MR-0001ADR-0008REQ-0002GOV-0001 — Stable reference diagnostics and resolver coverage

## Intent

Ensure that governed reference resolution remains complete, reproducible and diagnosable across entity types.

## Governance obligation

- The governed entity resolver registry must contain at most one active resolver for each referenceable entity type.
- Each active governed entity resolver must identify one authoritative source projection.
- Each active governed entity resolver must identify one eligibility provider.
- The governed reference validator must publish stable rule identifiers.
- The governed reference validator must distinguish noncanonical syntax from an unknown identifier.
- The governed reference validator must distinguish an unknown identifier from an ambiguous identifier.
- The governed reference validator must distinguish a disallowed entity type from failed semantic eligibility.
- The governed reference validator must distinguish title divergence from identity failure.
- The governed reference validator must order diagnostics deterministically.
- The governed reference validator must remain side-effect-free.
- A newly referenceable entity type must include positive and negative fixtures before activation.
- An editor adapter must not register an independent governed entity resolver.

## Verification obligations

- The verification must confirm resolver uniqueness for every active referenceable entity type.
- The verification must resolve every active entity type through its declared authoritative source.
- The verification must exercise the declared eligibility provider for every active entity type.
- The verification must compare emitted rule identifiers with the canonical diagnostic catalog.
- The verification must compare repeated diagnostic ordering for deterministic equivalence.
- The verification must cover valid, noncanonical, unknown, ambiguous, disallowed, title-divergent and ineligible fixtures.
- The verification must confirm that reference validation leaves documents and canonical sources unchanged.
- The verification must reject adapter-owned resolver registration.

## Failure conditions

- The verification must fail when one entity type has multiple active resolvers.
- The verification must fail when an active resolver lacks an authoritative source.
- The verification must fail when an active resolver lacks an eligibility provider.
- The verification must fail when a diagnostic uses an unknown stable rule identifier.
- The verification must fail when identical invalid input produces different diagnostic ordering.
- The verification must fail when an entity type is activated without positive and negative fixtures.
- The verification must fail when reference validation modifies a document or canonical source.
- The verification must fail when an editor adapter introduces an independent resolver.
