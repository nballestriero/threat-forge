# MR-0001ADR-0008REQ-0001 — Canonical Markdown representation of governed entity references

## Intent

Provide one readable and deterministic Markdown payload for references to canonical governed entities.

## Functional obligation

- A governed reference payload must represent exactly one canonical governed entity.
- A governed reference payload must use the form `[<canonical-id>] <canonical-title>`.
- The payload must begin with an opening square bracket.
- The payload identifier must equal the complete canonical identifier.
- The payload identifier must preserve canonical letter case.
- The closing square bracket must immediately follow the canonical identifier.
- The closing square bracket must be followed by exactly one ASCII space.
- The payload title must equal the canonical title resolved from the authoritative entity source.
- The payload must not contain leading or trailing whitespace.
- A body profile must declare every reference-bearing position.
- A body profile must declare any Markdown container outside the reference payload.
- The parser must remove only the container declared by the applicable body profile.
- The parser must return the authored identifier and authored title as separate values.
- The serializer must produce the canonical payload from a resolved identifier and canonical title.
- A governed reference payload must not originate or create the referenced entity.
- A non-reference-bearing position must remain ordinary Markdown prose.
- The canonical grammar must not accept parenthesized tokens, bare identifiers or Markdown links as governed reference payloads.

## Scope

- Includes: governed Markdown body profiles
- Includes: profile-declared reference-bearing positions
- Includes: canonical identifiers and canonical title mirrors
- Includes: profile-owned list or section containers
- Includes: future BAE, threat, finding, mitigation and snapshot references
- Excludes: ordinary identifier mentions in prose
- Excludes: external links and bibliographic citations
- Excludes: entity-specific origin and eligibility semantics
- Excludes: editor completion ordering

## Acceptance

- The requirement is accepted when `[BAE-0001] Canonical title` parses into one identifier and one title.
- The requirement is accepted when serialization emits exactly one ASCII space after the closing bracket.
- The requirement is accepted when parse and serialize preserve an unchanged canonical payload.
- The requirement is accepted when `(@BAE-0001) Canonical title` is rejected in a reference-bearing position.
- The requirement is accepted when a bare `BAE-0001` is rejected in a reference-bearing position.
- The requirement is accepted when `[BAE-0001](target)` is rejected in a reference-bearing position.
- The requirement is accepted when identical text outside a reference-bearing position remains ordinary prose.
- The requirement is accepted when parsing a reference leaves the referenced entity source unchanged.
