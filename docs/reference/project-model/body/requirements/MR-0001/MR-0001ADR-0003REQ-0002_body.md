# MR-0001ADR-0003REQ-0002 — Copertura implementativa dei requisiti governati

## Intent

Expose implementation coverage for every governed Requirement, including Requirements that have no linked implementation artifact.

## Functional obligation

- ThreatForge must derive one Requirement-centric implementation coverage view from the canonical Requirement registries and the implementation trace registry.
- The coverage view must include every governed Requirement exactly once.
- The coverage view must list the identifiers, types, states and applicable paths of all linked artifacts.
- The coverage view must list available verification commands and already detected registry-to-file inconsistencies.
- The coverage view must classify coverage as absent, planned only, scaffolded or containing at least one implemented artifact.
- The coverage view must identify Requirements with no implementation trace record explicitly.
- The coverage view must keep Requirement lifecycle state separate from implementation coverage state.
- The coverage view must not duplicate implementation paths inside Requirement registry records.

## Scope

- Includes: all canonical Functional and Governance Requirements
- Includes: planned, scaffolded, implemented, deprecated and superseded artifacts
- Includes: aggregation of multiple artifacts linked to one Requirement
- Includes: deterministic outputs for checks, reports, catalogs and UI views
- Excludes: automatic assessment of functional code quality
- Excludes: coverage inferred only from Markdown body prose
- Excludes: implementation paths persisted in Requirement records

## Acceptance

- The requirement is accepted when every canonical Requirement appears exactly once in the coverage view.
- The requirement is accepted when every linked artifact is shown with its applicable status and path.
- The requirement is accepted when a Requirement without trace records is reported as uncovered.
- The requirement is accepted when registry changes produce deterministic coverage-view changes.
- The requirement is accepted when no Requirement-to-code path is duplicated in the Requirement registry.
