# MR-0001ADR-0010REQ-0001 — Extensible canonical governed document model catalog

## Intent

Make the active governed document model and representation profile inventories extensible through one explicit canonical source without consumer-local cardinality assumptions.

## Functional obligation

- ThreatForge must treat the canonical document model index as the authoritative inventory of active governed document models.
- ThreatForge must derive the active representation profile inventory from the profiles referenced by canonical model entries.
- Shared model loaders must enumerate canonical model entries without enforcing a fixed total model count.
- Shared profile loaders must validate referenced canonical profiles without enforcing a fixed total profile count.
- Every canonical document model entry must reference exactly one registry profile and exactly one Markdown body profile.
- Every model extension must preserve stable model identifiers profile identifiers and controlled value references.
- Every deterministic consumer projection must derive its model inventory from the canonical document model sources.
- A consumer must not maintain an independent canonical inventory of governed document models.

## Scope

- Includes: Canonical document model index
- Includes: Representation profiles referenced by active model entries
- Includes: Shared document model source loading
- Includes: Deterministic model inventory projections
- Includes: Extension readiness for the Security Requirement model
- Excludes: Security Requirement model implementation
- Excludes: Security Requirement validation implementation
- Excludes: Governed document authoring changes
- Excludes: Governed Markdown assistance changes
- Excludes: Legacy graph and append-first mechanisms

## Acceptance

- The requirement is accepted when the canonical document model index is identified as the active model inventory.
- The requirement is accepted when every active model resolves exactly one registry profile and one Markdown body profile.
- The requirement is accepted when shared source loading derives model and profile inventories without fixed total cardinalities.
- The requirement is accepted when a newly registered canonical model can extend the inventory without modifying a consumer-local model list.
- The requirement is accepted when unregistered models and unresolved profile references remain outside the active inventory.
