# MR-0001ADR-0004REQ-0002 — Catalogo canonico dei campi controllati e dei metadati di presentazione

## Intento

Fornire una rappresentazione unica, interrogabile e indipendente dalla superficie applicativa per tutti i campi documentali controllati, i rispettivi valori e i metadati necessari a guidarne la selezione e la comprensione.

## Obbligo funzionale

Il Project Model deve esporre un catalogo canonico dei campi controllati derivato dai registri tassonomici e dagli altri registri governati applicabili.

Per ciascun campo controllato il catalogo deve dichiarare almeno:

- il nome canonico del campo;
- la fonte canonica che ne governa i valori;
- il contesto di applicazione, inclusi registro e tipo di record;
- l'eventuale obbligatorieta;
- le relazioni applicabili con altri campi.

Per ciascun valore controllato il catalogo deve dichiarare almeno:

- il valore macchina canonico;
- una label leggibile;
- un significato o una descrizione adatta anche a suggerimenti e tooltip;
- se il valore e selezionabile e memorizzabile;
- se il valore e astratto, vietato, deprecato o storico;
- gli eventuali alias esplicitamente ammessi o vietati;
- un eventuale colore di presentazione, considerato metadato facoltativo e non significato normativo.

## Ambito

Il catalogo deve supportare almeno i campi controllati di macro-requirement, ADR, requirement, registri di governance, implementation trace e risultati dei controlli.

Il catalogo deve essere indipendente da CLI, VS Code, API e frontend web. Tali superfici possono consumarlo o consumarne proiezioni deterministiche, ma non diventano fonti canoniche dei valori o delle descrizioni.

Il body Markdown non diventa fonte canonica dei campi strutturati. I valori eventualmente ripetuti nel body devono essere derivati o verificati rispetto al record canonico del registro.

## Acceptance

Il requisito e soddisfatto quando:

- ogni campo controllato incluso nell'ambito dichiara una fonte canonica univoca;
- ogni valore selezionabile dispone di label e descrizione;
- valori astratti o vietati non risultano selezionabili o memorizzabili;
- gli alias sono espliciti e non inferiti dal codice;
- il catalogo puo alimentare schema editoriale, validazione CLI, API e presentazione web senza duplicare enum, descrizioni o colori;
- una modifica della fonte canonica produce una variazione deterministica del catalogo o rende stale le sue proiezioni;
- la mancata provenienza o l'ambiguita di un campo controllato impedisce la generazione del catalogo.
