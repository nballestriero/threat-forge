# MR-0001REQ-0026GOV-0002 — LLM Governed Development Guide

## Intent

LLM-assisted work needs a stricter operating guide than ordinary human notes because an LLM can otherwise generate broad changes that skip project-model governance.

The LLM guide must force changes through the same documentation-as-code and security-first workflow used by programmers, while also making explicit how to recover context, read authoritative sources, and avoid treating working-plan summaries as canonical truth.

## Parent Functional Requirement

Parent functional requirement: `MR-0001REQ-0026`.

This specialized governance requirement applies the governed guide-placement rule to the LLM-facing operating guide.

## Specialized Requirement

The project must provide an LLM governed development guide under the Diátaxis how-to space.

The guide path must be:

```text
docs/how-to/governed-development/llm-governed-development-guide.md
```

The guide must explain how LLM-assisted changes should read the project model, select the correct macro-requirement, create or update ADRs and requirements before implementation, update the graph, respect append-first governance, and use governed gates before routine commit/push.

## Scope

This requirement applies to LLM-assisted work on threat-forge and future child projects governed by threat-forge.

It covers source-of-truth selection, microstep discipline, documentation placement, traceability, implementation boundaries, validation, and handoff behavior.

It does not define prompt-engineering internals, model-provider configuration, AI agent orchestration, or future STRIDE-AI analysis behavior.

## Rules

- The LLM guide must live under `docs/how-to/governed-development/`.
- The guide must instruct LLM-assisted work to read authoritative project-model sources before proposing changes.
- The guide must distinguish canonical sources from dynamic handoff or working-plan summaries.
- The guide must require selecting the correct macro-requirement before adding ADRs, requirements, graph relations, or code.
- The guide must require small requirements and one governed micropasso at a time.
- The guide must forbid implementation-first changes for governed behavior.
- The guide must require graph updates before implementation is considered traceable.
- The guide must require JSDoc traceability for source artifacts when applicable.
- The guide must require `npm run repo:check` and the governed commit-push runner for routine repository operations.
- The guide must require explicit disclosure when a direct Git exception is used.

## Acceptance Criteria

  Given MR-0001 requires an LLM governed development guide
  When the documentation tree is inspected

  And the guide explains the LLM governed development workflow

  Given an LLM is asked to implement governed behavior
  When it follows the LLM governed development guide

  And creates or updates ADRs, requirements, and graph relations when needed
  And only then proposes implementation and verification steps
