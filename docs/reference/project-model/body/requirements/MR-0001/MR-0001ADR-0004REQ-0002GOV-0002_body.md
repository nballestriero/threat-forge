# MR-0001ADR-0004REQ-0002GOV-0002 — Freshness deterministica delle proiezioni dei campi controllati

## Intento

Garantire che ogni proiezione consumata da editor, tool, API o frontend rimanga sincronizzata con le fonti canoniche dei campi controllati.

## Obbligo di governance

Le proiezioni generate dal catalogo dei campi controllati devono essere deterministiche, revisionabili e verificabili rispetto allo snapshot corrente delle fonti canoniche.

Una modifica a una tassonomia, a un registro sorgente o ai metadati di un valore deve:

- produrre una modifica deterministica delle proiezioni interessate; oppure
- rendere il controllo di freshness non superato fino alla rigenerazione.

I controlli non devono aggiornare silenziosamente gli artefatti durante la verifica.

## Controlli minimi

La copertura deve includere almeno:

- valore concreto selezionabile accettato;
- valore astratto o vietato respinto;
- alias ammesso risolto secondo la fonte canonica;
- alias assente o vietato respinto;
- valore senza label o descrizione respinto quando selezionabile;
- proiezione stale rilevata;
- provenienza mancante o ambigua rilevata;
- determinismo a parita di snapshot canonico;
- assenza di mutazioni durante la modalita di controllo.

## Failure mode

Il controllo deve fallire quando una proiezione non corrisponde alle fonti correnti, quando un consumatore espone valori o descrizioni divergenti oppure quando la verifica modifica il workspace.
