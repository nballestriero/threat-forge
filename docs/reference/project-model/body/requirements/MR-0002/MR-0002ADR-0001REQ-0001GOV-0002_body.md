# MR-0002ADR-0001REQ-0001GOV-0002 — Copertura deterministica della pianificazione implementativa

## Intento

Dimostrare che il pianificatore implementativo applica realmente i vincoli read-only e rifiuta input incompatibili con il modello governato.

## Obbligo di governance

Il pianificatore e il relativo adapter VS Code devono essere verificati da un controllo deterministico registrato nel catalogo locale dei check.

Il controllo deve verificare almeno:

- presenza della tracciabilità del tool verso requisito, decisione e macro-requirement;
- presenza del task VS Code e degli argomenti obbligatori;
- successo di un caso valido con output completo;
- rifiuto deterministico dei principali input invalidi;
- assenza di mutazioni del working tree durante la pianificazione e la verifica.

## Controlli minimi

Le fixture negative devono coprire requisito inesistente, tipo non supportato, path assoluto, attraversamento della directory padre, input obbligatorio mancante e assenza della modalità `--dry-run` esplicita.

## Failure mode

Il controllo deve fallire quando il pianificatore o il task perdono un vincolo obbligatorio, una fixture negativa passa inaspettatamente, il caso valido non produce il piano previsto oppure il working tree cambia durante l'esecuzione.
