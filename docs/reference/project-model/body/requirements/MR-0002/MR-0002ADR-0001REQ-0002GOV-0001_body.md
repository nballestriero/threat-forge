# MR-0002ADR-0001REQ-0002GOV-0001 — View-model canonico e tooltip accessibili

## Intento

Impedire che backend e frontend ricostruiscano autonomamente il significato dei campi controllati e garantire che le descrizioni siano accessibili.

## Obbligo di governance

Il backend deve risolvere i metadati dei campi controllati attraverso il catalogo canonico e deve esporre un view-model stabile e indipendente dalla struttura fisica dei registri.

Il frontend non deve dichiarare localmente:

- valori ammessi;
- label di dominio;
- descrizioni;
- alias;
- colori con significato governato;
- regole di applicabilita.

Ogni componente che rappresenta un campo controllato deve rendere disponibile la descrizione canonica tramite hover, focus da tastiera, tecnologia assistiva e alternativa testuale quando il tooltip non e disponibile.

Il colore puo supportare la lettura ma non deve essere l'unico mezzo per comunicare stato o significato.

## Controlli minimi

I controlli devono verificare almeno:

- provenienza dei metadati restituiti dall'API;
- corrispondenza tra valore corrente e value set applicabile;
- assenza di enum e descrizioni di dominio nel frontend;
- tooltip o descrizione associata al valore;
- apertura tramite hover e focus;
- presenza di label testuale;
- assenza di informazione comunicata soltanto dal colore;
- comportamento definito sui dispositivi senza hover;
- coerenza tra tooltip e view-model API;
- separazione tra record strutturato e rendering del body Markdown.

## Failure mode

Il controllo deve fallire quando API o frontend espongono significati non presenti nelle fonti canoniche, quando la descrizione e accessibile soltanto con il mouse, quando il colore e l'unico indicatore o quando il frontend continua a funzionare grazie a una copia locale divergente.
