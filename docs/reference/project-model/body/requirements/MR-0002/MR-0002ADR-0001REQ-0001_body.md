# MR-0002ADR-0001REQ-0001 — Pianificazione guidata di un artefatto implementativo da requisito governato

## Intent

Reduce initial implementation mistakes by producing a deterministic artifact plan before any source or registry mutation.

## Functional obligation

- ThreatForge must allow an author to select an existing governed Requirement.
- The planner must accept the proposed artifact type, title and repository-relative path.
- The planner must derive the owning Macro-requirement and Decision from the selected Requirement.
- The planner must validate the artifact identifier, type and path before any write operation.
- The planner must display the linked Requirement, target path, required trace declarations and verification command.
- The initial planner operation must remain read-only.
- The planner must be invokable from the canonical repository root and through a VS Code task.

## Scope

- Includes: existing Functional and Governance Requirements
- Includes: tool, application component, test and fixture planning
- Includes: terminal and IDE-readable plan output
- Includes: canonical repository-root execution
- Excludes: source file creation
- Excludes: implementation trace mutation
- Excludes: automatic commit, push or application-code generation

## Acceptance

- The requirement is accepted when a governed command accepts a valid Requirement and minimal artifact data.
- The requirement is accepted when the command produces the same plan for the same repository snapshot and input.
- The requirement is accepted when invalid identifiers, types or paths are rejected before writing.
- The requirement is accepted when the command is available through VS Code.
- The requirement is accepted when planning leaves the repository unchanged.
