# MR-0002ADR-0006REQ-0002GOV-0001 — Thin VS Code adapter without duplicated rules

## Intent

Prevent the VS Code integration from becoming an independent source of governed documentation semantics.

## Governance obligation

- The VS Code adapter must delegate semantic analysis to the shared Markdown assistance core.
- The VS Code adapter must not contain canonical section inventories.
- The VS Code adapter must not contain controlled documentation value sets.
- The VS Code adapter must not reinterpret canonical diagnostic rule identifiers.
- The VS Code adapter must preserve canonical completion ordering returned by the core.
- The VS Code adapter must keep command tasks separate from live document analysis.

## Verification obligations

- The verification must inspect the adapter for duplicated canonical headings and controlled values.
- The verification must compare adapter diagnostics with direct core diagnostics for identical input.
- The verification must compare adapter completion ordering with direct core completion ordering.
- The verification must confirm that the adapter passes unsaved document text to the core.
- The verification must confirm that no completion action performs an unconfirmed repository mutation.

## Failure conditions

- The verification must fail when the adapter contains a manually maintained canonical section inventory.
- The verification must fail when the adapter contains a manually maintained controlled value set.
- The verification must fail when adapter output changes the semantic order returned by the core.
- The verification must fail when live completion performs a repository write.
