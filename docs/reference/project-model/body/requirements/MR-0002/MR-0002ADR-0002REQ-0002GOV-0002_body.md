# MR-0002ADR-0002REQ-0002GOV-0002 — Idempotent materialization and fail-closed repository operation

## Intent

Ensure that automatic projection materialization is deterministic, rollback-capable and unable to bypass repository governance.

## Governance obligation

- The runner must snapshot every declared generated path before the first materializer write operation.
- The runner must execute one complete materialization pass before projection verification.
- The runner must execute a second complete materialization pass to verify idempotence.
- The runner must compare declared generated-path content after the first and second materialization passes.
- Every active materializer must produce byte-identical declared outputs on the second pass when canonical inputs are unchanged.
- The runner must stop at the first materializer write, check, boundary, idempotence or repository-gate failure.
- The runner must restore declared generated paths to their pre-run state after any pre-stage failure.
- The runner must preserve pre-existing changes outside declared generated paths during rollback.
- The runner must not execute `git add`, `git commit` or `git push` after any pre-stage failure.
- The runner must stage repository changes only after materialization, idempotence verification and `tools/repo-check.mjs` succeed.

## Verification obligations

- The verification must exercise a stale projection that becomes current before the repository gate.
- The verification must exercise an already current projection that remains unchanged.
- The verification must execute a deliberately non-idempotent materializer fixture.
- The verification must execute a materializer check failure fixture.
- The verification must confirm rollback of declared generated paths after every pre-stage failure class.
- The verification must confirm preservation of unrelated pre-existing working-tree changes.
- The verification must confirm the absence of Git stage, commit and push operations after a failure.

## Failure conditions

- The verification must fail when the second materialization pass changes a declared generated path.
- The verification must fail when a pre-stage failure leaves a generated path different from its pre-run state.
- The verification must fail when rollback modifies an unrelated pre-existing working-tree change.
- The verification must fail when `git add`, `git commit` or `git push` occurs after a materializer or gate failure.
- The verification must fail when `tools/repo-check.mjs` executes before materialization and idempotence verification complete.
