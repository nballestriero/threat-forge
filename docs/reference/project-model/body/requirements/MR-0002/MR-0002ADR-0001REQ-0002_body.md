# MR-0002ADR-0001REQ-0002 — Presentazione web dei campi documentali controllati

## Intento

Rendere comprensibili e navigabili i campi controllati nella pagina web di consultazione della documentazione, usando gli stessi metadati disponibili durante l'authoring.

## Obbligo funzionale

L'API del Project Model deve poter fornire, insieme al valore corrente di un campo controllato:

- nome canonico del campo;
- valore macchina;
- label leggibile;
- descrizione o significato;
- contesto e fonte canonica;
- stato di selezionabilita, deprecazione o divieto;
- eventuale colore di presentazione;
- quando utile, l'insieme dei valori applicabili al record visualizzato.

La pagina web deve rappresentare i campi controllati con componenti coerenti, quali badge, proprieta o selettori nelle future viste modificabili.

La descrizione canonica deve essere disponibile al passaggio del mouse e tramite interazione da tastiera o tecnologia assistiva.

## Ambito

La prima versione puo essere read-only e mostrare il valore corrente con descrizione.

Le future funzioni di modifica devono riutilizzare lo stesso contratto per popolare selettori e diagnostica, senza introdurre un secondo catalogo frontend.

I dati discorsivi del body Markdown restano distinti dai metadati strutturati del registro.

## Acceptance

Il requisito e soddisfatto quando:

- un campo controllato visualizzato mostra una label comprensibile;
- la descrizione canonica e accessibile tramite hover e focus;
- i valori deprecati, vietati o storici sono distinguibili secondo i metadati;
- la UI non contiene enum o descrizioni di dominio hardcoded;
- il valore mostrato e riconducibile al record e alla tassonomia canonici;
- una modifica dei metadati canonici si riflette attraverso API e UI dopo la rigenerazione o il normale caricamento dei dati.
