# MR-0002ADR-0001REQ-0002 — Presentazione web dei campi documentali controllati

## Intent

Make governed controlled fields understandable and navigable in the web documentation view by reusing the same canonical metadata available during authoring.

## Functional obligation

- The Project Model API must expose the canonical field name together with each displayed controlled value.
- The API must expose the machine value, readable label, description, context and governing source.
- The API must expose selection, deprecation, prohibition and historical metadata when applicable.
- The API must expose optional presentation color and context-applicable value choices when useful.
- The web UI must render controlled fields through consistent components such as badges, properties or future selectors.
- The web UI must expose canonical descriptions through pointer hover, keyboard focus and assistive technology.
- Future editable web views must reuse the same controlled-field contract instead of introducing frontend-owned enums.
- Markdown body prose must remain separate from structured registry metadata.

## Scope

- Includes: read-only controlled-field presentation
- Includes: canonical labels, descriptions and provenance
- Includes: accessibility through hover, focus and assistive technology
- Includes: future selector population from the same API contract
- Excludes: frontend-hardcoded domain enums or descriptions
- Excludes: Markdown body text as structured metadata authority

## Acceptance

- The requirement is accepted when a displayed controlled field has a readable label.
- The requirement is accepted when its canonical description is available through hover and keyboard focus.
- The requirement is accepted when deprecated, forbidden and historical values are visually distinguishable.
- The requirement is accepted when the UI contains no hardcoded domain enum or description.
- The requirement is accepted when every displayed value is traceable to its canonical record and taxonomy.
- The requirement is accepted when canonical metadata changes propagate through the API and normal projection refresh.
