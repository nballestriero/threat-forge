# MR-0002ADR-0004REQ-0003GOV-0002 — Validazione deterministica del catalogo, dello schema e del wizard

## Intento

Garantire che catalogo, JSON Schema e wizard CLI rappresentino in modo coerente e verificabile lo stesso contratto di authoring.

## Obbligo di governance

Il catalogo, lo schema e il wizard devono essere validati deterministicamente rispetto alle fonti canoniche e tra loro.

A parita di snapshot del repository:

- l'ordinamento degli elementi deve essere stabile;
- il contenuto generato deve essere riproducibile;
- gli enum dello schema devono coincidere con i valori del catalogo;
- le descrizioni dello schema devono coincidere con i significati canonici;
- le condizioni sul requisito padre devono coincidere con le regole del tipo concreto;
- preview e creazione devono produrre lo stesso piano documentale;
- la creazione deve applicare interamente il piano oppure non applicarlo.

## Controlli minimi

La copertura positiva e negativa deve includere almeno:

- tipo concreto valido;
- valore `specialized` usato impropriamente come tipo;
- tipo non registrato;
- macro-requirement inesistente;
- ADR inesistente o appartenente a un'altra macro-requirement;
- requisito padre inesistente o appartenente a un'altra macro-requirement;
- requisito padre vietato dal tipo selezionato;
- requisito padre obbligatorio ma assente;
- divergenza tra catalogo e JSON Schema;
- tentativo di scrittura senza conferma;
- errore durante la creazione del secondo artefatto;
- riesecuzione di una creazione gia applicata;
- assenza di mutazioni dopo ogni rifiuto o errore.

## Failure mode

Qualsiasi violazione del contratto deve produrre un errore deterministico e non deve lasciare record, body o file temporanei parziali.

Un controllo successivo alla creazione che fallisce deve essere riportato come fallimento dell'operazione di authoring e non come creazione completata con successo.
