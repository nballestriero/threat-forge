# MR-0002ADR-0006REQ-0004 — Governed entity reference assistance in Markdown bodies

## Intent

Provide contextual completion, hover, diagnostics and quick fixes for governed entity references in unsaved Markdown bodies.

## Functional obligation

- The Markdown assistance core must identify reference-bearing positions from the applicable canonical body profile.
- The Markdown assistance core must parse authored reference payloads through the canonical governed entity reference grammar.
- The Markdown assistance core must obtain candidate entities through the registered canonical resolver for each allowed entity type.
- The Markdown assistance core must evaluate candidate eligibility through the entity-owning model.
- The Markdown assistance core must return only resolvable and eligible completion candidates.
- Each completion candidate must expose the canonical identifier.
- Each completion candidate must expose the canonical title.
- Each completion candidate must expose the canonical entity type.
- Each completion candidate must insert the complete canonical reference payload.
- The Markdown assistance core must prioritize eligible identifiers already referenced in the current unsaved body.
- The Markdown assistance core must prioritize eligible identifiers related to the current governed document after identifiers already referenced in the current body.
- The Markdown assistance core must include remaining eligible identifiers after document-related identifiers.
- The Markdown assistance core must return each canonical identifier at most once in a completion result.
- Hover information must expose the canonical identifier, title, entity type and authoritative source.
- Hover information for a BAE must expose its meaning, governed origin, provenance and lifecycle state when present in the canonical projection.
- The Markdown assistance core must emit stable diagnostics for noncanonical syntax, unknown identifiers, ambiguous identifiers, disallowed entity types, divergent titles and failed eligibility.
- A divergent title must expose a quick fix that replaces the complete payload with the canonical payload.
- A resolvable noncanonical form must expose a quick fix only when the current position allows the resolved entity type.
- The Markdown assistance core must not offer implicit entity creation from an unknown reference.
- The Markdown assistance core must not propose governed entity references outside profile-declared reference-bearing positions.
- Completion, hover, diagnostics and quick fixes must leave the document and repository unchanged.

## Scope

- Includes: unsaved Macro-requirement Markdown bodies
- Includes: unsaved ADR Markdown bodies
- Includes: unsaved Functional Requirement Markdown bodies
- Includes: unsaved Governance Requirement Markdown bodies
- Includes: canonical BAE references
- Includes: future registered governed entity types
- Includes: canonical replacement quick fixes
- Excludes: implicit governed entity creation
- Excludes: direct registry mutation
- Excludes: editor-owned entity semantics
- Excludes: references outside profile-declared positions

## Acceptance

- The requirement is accepted when typing in a BAE reference-bearing position returns eligible BAE candidates as canonical payloads.
- The requirement is accepted when identifiers already referenced in the current body appear before other eligible identifiers.
- The requirement is accepted when document-related identifiers appear before remaining eligible identifiers.
- The requirement is accepted when one canonical identifier appears at most once in the completion result.
- The requirement is accepted when hover over a resolved BAE exposes its canonical identity, meaning, origin, provenance and lifecycle state.
- The requirement is accepted when a divergent title produces a stable diagnostic and a canonical replacement quick fix.
- The requirement is accepted when a descendant-only BAE origin produces an ineligible reference diagnostic.
- The requirement is accepted when an unknown identifier produces no implicit entity creation action.
- The requirement is accepted when an ordinary prose position produces no governed reference candidates.
- The requirement is accepted when assistance leaves the unsaved document and repository unchanged.
