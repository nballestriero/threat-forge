# MR-0002ADR-0003REQ-0001GOV-0002 — Copertura deterministica della creazione di scaffold

## Intento

Dimostrare che lo scaffolder rispetta creazione, tracciabilità, non sovrascrittura e rollback senza affidarsi a verifiche manuali.

## Obbligo di governance

Un controllo deterministico deve verificare:

- presenza delle dichiarazioni di tracciabilità nel tool;
- mapping corretto del task VS Code;
- presenza della conferma esplicita;
- creazione positiva in un workspace isolato;
- registrazione dello stato `scaffolded`;
- validità del risultato tramite il checker di implementation trace;
- rifiuto deterministico dei casi negativi governati;
- assenza di modifiche al repository reale durante il controllo.

## Controlli minimi

Le fixture negative devono coprire almeno:

- conferma mancante;
- requisito sconosciuto;
- tipo non materializzabile;
- path non sicuro;
- file già esistente;
- path già registrato.

## Failure mode

Il controllo deve fallire quando il contratto statico diverge, il caso positivo non produce file e record coerenti, il checker di tracciabilità rifiuta lo scaffold o una fixture negativa passa inaspettatamente.
