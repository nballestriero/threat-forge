# MR-0002ADR-0005REQ-0001 — Catalogo locale di task VS Code ThreatForge

## Intent

Expose governed local ThreatForge commands through Visual Studio Code without duplicating command logic or introducing an editor-specific domain implementation.

## Functional obligation

- The ThreatForge workspace must maintain a local VS Code task catalog under `.vscode/tasks.json`.
- The task catalog must expose the canonical repository check.
- The task catalog must expose applicable individual governed checks.
- The task catalog must expose read-only previews for Functional and Governance Requirement creation.
- The task catalog must expose a read-only handoff archive preview.
- Each task must execute from the canonical repository root.
- Each user-facing task label must use the `ThreatForge:` prefix.
- Each task must delegate behavior to the corresponding governed CLI command.

## Scope

- Includes: local `.vscode/tasks.json`
- Includes: interactive inputs for governed command parameters
- Includes: repository-root command execution
- Includes: safe preview and dry-run tasks
- Excludes: a dedicated VS Code extension
- Excludes: domain logic duplicated in task configuration
- Excludes: unconfirmed governed document or handoff writes

## Acceptance

- The requirement is accepted when VS Code exposes the governed task catalog from the repository root.
- The requirement is accepted when each task invokes its registered ThreatForge command.
- The requirement is accepted when preview tasks leave the repository unchanged.
- The requirement is accepted when user-facing labels follow the canonical prefix convention.
- The requirement is accepted when task configuration contains no duplicate implementation logic.
