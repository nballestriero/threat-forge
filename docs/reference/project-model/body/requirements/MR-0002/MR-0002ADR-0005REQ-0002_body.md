# MR-0002ADR-0005REQ-0002 — Authoring guidato dei requisiti tramite VS Code

## Intento

Consentire agli autori di utilizzare da VS Code il contratto governato di authoring dei requisiti senza inserire manualmente identificativi canonici, senza modificare direttamente i registri canonici e senza introdurre una custom extension.

## Obbligo funzionale

Il workspace ThreatForge deve esporre tramite VS Code:

- un task per avviare la preview guidata di un nuovo requisito;
- un task per avviare la creazione guidata con conferma esplicita;
- un'associazione tra lo JSON Schema generato e i documenti YAML di richiesta authoring con nome `*.requirement-authoring.yml`;
- snippet governati per la struttura dei body Markdown;
- diagnostica editoriale per valori non validi e campi mancanti.

I documenti `*.requirement-authoring.yml` rappresentano input IDE-independent per il core e non sostituiscono i registri YAML canonici dei requisiti.

I task devono avviare il wizard del core indipendente dall'IDE.

La selezione dinamica di macro-requirement, ADR, tipo concreto e requisito padre deve essere eseguita dal wizard utilizzando il catalogo derivato dalle fonti canoniche. Tali valori non devono essere mantenuti come opzioni statiche dentro `.vscode/tasks.json`.

Il task di preview non deve produrre side effect.

Il task di creazione deve mostrare la stessa preview e delegare al core la richiesta di conferma e l'operazione atomica sui registri e body governati.

## Ambito

Incluso:

- `.vscode/tasks.json`;
- associazione locale dello schema YAML ai documenti `*.requirement-authoring.yml`;
- snippet Markdown;
- apertura del wizard dalla root del repository;
- visualizzazione degli errori prodotti dal core e dallo schema.

Escluso:

- custom extension VS Code;
- associazione dello schema di richiesta authoring ai registri YAML canonici;
- modifica diretta dei registri YAML canonici tramite diagnostica o completamento editoriale;
- lettura autonoma dei registri da parte della configurazione `.vscode`;
- logica di generazione o validazione implementata nei task;
- commit o push dall'editor;
- valori canonici codificati staticamente nella configurazione editor.

## Acceptance

Il requisito e soddisfatto quando, aprendo la root del repository in VS Code, un utente puo:

- avviare una preview guidata dalla palette dei task;
- avviare una creazione che rimane annullata finche non viene fornita conferma esplicita;
- selezionare MR, ADR, tipo e requisito padre tra valori derivati dai registri;
- ricevere diagnostica YAML sui documenti `*.requirement-authoring.yml` per campi mancanti o valori non ammessi;
- usare snippet Markdown coerenti con i body governati;
- delegare esclusivamente al core la generazione e la scrittura dei registri e body canonici;
- completare il flusso senza che `.vscode` contenga una copia delle regole canoniche.
