# MR-0002ADR-0005REQ-0002 — Authoring guidato dei requisiti tramite VS Code

## Intent

Use the shared governed document authoring contract from Visual Studio Code without manual identifier calculation or direct canonical registry editing.

## Functional obligation

- The ThreatForge workspace must expose a VS Code task for guided Requirement preview.
- The ThreatForge workspace must expose a VS Code task for confirmed Requirement creation.
- The workspace must associate the generated JSON Schema with `*.governed-document-authoring.yml` request documents.
- The workspace must provide governed Markdown snippets applicable to Requirement bodies.
- The workspace must surface schema diagnostics for missing fields and invalid values.
- The VS Code tasks must invoke the IDE-independent authoring core.
- The authoring core must derive selectable Macro-requirements, Decisions, concrete types and parent Requirements dynamically from the canonical catalog.
- `.vscode/tasks.json` must not contain static copies of canonical domain choices.
- The preview task must remain free of repository side effects.
- The creation task must reuse the preview and delegate confirmation and atomic writes to the authoring core.

## Scope

- Includes: VS Code task integration
- Includes: YAML Schema association for authoring request files
- Includes: governed Markdown snippets and editor diagnostics
- Includes: dynamic wizard choices derived from canonical sources
- Excludes: a custom VS Code extension
- Excludes: schema association with canonical Requirement registries
- Excludes: direct registry editing through editor completion
- Excludes: generation or validation logic implemented in `.vscode`
- Excludes: commit and push from the editor

## Acceptance

- The requirement is accepted when an author can start preview and creation from the VS Code task palette.
- The requirement is accepted when creation remains cancelled until explicit confirmation.
- The requirement is accepted when MR, ADR, type and parent choices come from canonical registries.
- The requirement is accepted when request documents receive YAML diagnostics for missing or invalid data.
- The requirement is accepted when Markdown snippets match governed body structures.
- The requirement is accepted when only the authoring core generates and writes canonical records and bodies.
- The requirement is accepted when `.vscode` contains no duplicate canonical domain rules.
