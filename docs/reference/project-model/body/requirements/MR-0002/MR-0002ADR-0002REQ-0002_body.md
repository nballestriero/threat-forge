# MR-0002ADR-0002REQ-0002 — Deterministic materialization before governed repository gates

## Intent

Keep repository projections current without requiring authors to execute separate generation commands before a governed commit and push.

## Functional obligation

- The governed repository operation runner must materialize every active registered repository projection before the read-only repository gate in `--commit-push` mode.
- The runner must execute active materializers in canonical registry order.
- The runner must execute each materializer using only its registered write command and arguments.
- The runner must execute each materializer verification using only its registered check command and arguments.
- The runner must verify materializer idempotence before executing `tools/repo-check.mjs`.
- The runner must execute `tools/repo-check.mjs` only after every active registered projection is current.
- The runner must include generated projection changes in the same staged diff as the canonical source changes that caused them.
- The runner must preserve read-only behavior in `--check` mode.
- The runner must not require an author to invoke materializer write commands manually in the normal commit-push workflow.
- The runner must not perform a Git stage, commit or push before materialization and repository verification succeed.

## Scope

- Includes: registered repository projection materializers
- Includes: governed `--commit-push` pre-gate execution
- Includes: generated schemas and editor adapter projections
- Includes: generated-file inclusion in the governed commit
- Excludes: repository mutation by `tools/repo-check.mjs`
- Excludes: repository mutation by runner `--check` mode
- Excludes: execution of unregistered generation commands

## Acceptance

- The requirement is accepted when a stale registered projection is updated automatically after `--commit-push` starts and before `tools/repo-check.mjs` runs.
- The requirement is accepted when a current registered projection remains byte-identical after materialization.
- The requirement is accepted when generated projection changes are staged with the canonical source changes that produced them.
- The requirement is accepted when a materializer failure prevents every Git mutation.
- The requirement is accepted when runner `--check` mode and `tools/repo-check.mjs` leave repository files unchanged.
