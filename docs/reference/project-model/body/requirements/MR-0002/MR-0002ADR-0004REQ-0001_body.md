# MR-0002ADR-0004REQ-0001 — Generatore deterministico di documenti governati

## Intent

Prevent divergence between governed YAML records and Markdown bodies by generating both representations from validated author input.

## Functional obligation

- ThreatForge must provide a local deterministic generator for governed Requirements.
- The generator must support every active concrete Requirement model whose canonical authoring provider coverage is complete.
- The generator must derive Requirement model identity and discriminator rules from the canonical document model and requirement registry profiles.
- The generator must derive the next canonical identifier from the selected ownership context.
- The generator must derive the canonical Markdown body path.
- The generator must produce the registry record and associated Markdown body as one operation.
- The generator must mirror the registry identifier and title in the canonical body H1.
- The generator must provide a read-only dry-run preview before write mode.
- The generator must reject invalid or incomplete ownership relations before writing.

## Scope

- Includes: generation of active concrete Requirement models exposed by the canonical authoring catalog
- Includes: explicit model-specific authoring providers checked against the canonical model inventory
- Includes: deterministic identifiers, body paths and H1 headings
- Includes: dry-run and confirmed write modes
- Excludes: manual identifier calculation
- Excludes: independent record or body creation
- Excludes: autonomous authoring of normative domain content

## Acceptance

- The requirement is accepted when dry-run displays the complete proposed registry record and body without mutation.
- The requirement is accepted when confirmed write mode creates one coherent record-body pair.
- The requirement is accepted when every generated Requirement variant uses the identifier, discriminator, ownership and relation rules declared by its canonical model and provider.
- The requirement is accepted when the generated body H1 exactly mirrors registry `id` and `title`.
- The requirement is accepted when invalid ownership or an existing target causes no partial write.
