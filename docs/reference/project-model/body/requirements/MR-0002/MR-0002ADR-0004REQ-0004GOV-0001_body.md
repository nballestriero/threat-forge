# MR-0002ADR-0004REQ-0004GOV-0001 — Preview obbligatoria, conferma esplicita e scrittura atomica

## Intento

Impedire mutazioni parziali o non intenzionali durante l'authoring guidato della documentazione governata.

## Obbligo di governance

Il core deve distinguere in modo esplicito:

- validazione della richiesta;
- pianificazione e preview senza side effect;
- applicazione confermata;
- controlli successivi alla scrittura.

Qualsiasi modalita che possa modificare registri o body deve richiedere un token di conferma esplicito e documentato.

Le operazioni su piu artefatti devono essere trattate come una singola transazione logica con rollback in caso di errore.

## Controlli minimi

I controlli devono verificare almeno:

- preview priva di mutazioni;
- scrittura respinta senza conferma;
- conferma errata respinta;
- file esistente non sovrascritto quando il contratto prevede create-only;
- rollback del registro quando fallisce la creazione del body;
- rollback del body quando fallisce l'aggiornamento del registro;
- esecuzione dei gate applicabili dopo una scrittura riuscita;
- report deterministico dell'operazione.

## Failure mode

Il controllo deve fallire in presenza di una mutazione durante la preview, di una scrittura senza conferma, di un artefatto parziale o di un successo dichiarato senza l'esecuzione dei controlli previsti.
