# MR-0002ADR-0002REQ-0002GOV-0001 — Registered materializers and declared output boundaries

## Intent

Prevent the governed repository runner from becoming an independent or unbounded source of projection-generation behavior.

## Governance obligation

- A canonical materialization registry must be the sole source of active repository materializers and their execution order.
- Each materializer record must declare a stable identifier.
- Each materializer record must declare a controlled lifecycle status.
- Each materializer record must declare its write command and ordered arguments.
- Each materializer record must declare its check command and ordered arguments.
- Each materializer record must declare every repository-relative generated path that it can modify or create.
- Each materializer record must declare the governed Requirement identifiers that justify the materializer.
- The runner must execute only active materializer records.
- The runner must invoke materializer commands without a shell.
- The runner must reject unsafe, absolute or root-escaping command and output paths.
- The runner must reject overlapping generated paths across active materializer records.
- The runner must detect newly modified or created paths introduced by each materializer.
- The runner must not accept a materializer-introduced change outside that materializer's declared generated paths.
- The runner must not contain a hard-coded inventory of projection-specific commands or output paths.

## Verification obligations

- The verification must validate the materialization registry structure and controlled values.
- The verification must validate stable identifiers, command arguments and generated paths for every active record.
- The verification must compare materializer-introduced working-tree changes with the declared generated paths.
- The verification must cover unsafe paths, duplicate identifiers, overlapping outputs and undeclared output mutations.
- The verification must confirm that registry order determines execution order.
- The verification must confirm that disabled or deprecated materializers are not executed.

## Failure conditions

- The verification must fail when the runner executes an unregistered materializer.
- The verification must fail when a materializer changes an undeclared path.
- The verification must fail when a generated path is absolute or resolves outside the repository root.
- The verification must fail when active materializers declare overlapping generated paths.
- The verification must fail when the runner contains a projection-specific hard-coded command inventory.
- The verification must fail when execution order differs from canonical registry order.
