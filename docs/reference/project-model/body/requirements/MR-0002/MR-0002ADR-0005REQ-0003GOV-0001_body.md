# MR-0002ADR-0005REQ-0003GOV-0001 — Adapter VS Code sottile e generato dalle fonti canoniche

## Intento

Impedire che configurazioni, task, snippet o schemi VS Code diventino una seconda implementazione del Project Model.

## Obbligo di governance

L'adapter VS Code deve essere limitato a:

- associazione tra pattern di file e schema;
- raccomandazione delle estensioni necessarie;
- task che invocano tool governati;
- presentazione delle proiezioni generate dal core.

Enum, descrizioni, relazioni, alias, identificativi e regole condizionali devono essere derivati dal catalogo canonico e non mantenuti manualmente nei file `.vscode`.

La materializzazione deve preservare le configurazioni non gestite e deve essere idempotente.

## Controlli minimi

I controlli devono verificare almeno:

- associazione dello schema ai soli file di richiesta previsti;
- assenza di associazione diretta ai registri canonici;
- schema corrente rispetto alle fonti;
- task mappati ai tool governati;
- assenza di liste operative duplicate in task, settings e snippet;
- idempotenza della materializzazione;
- nessuna modifica a file non gestiti.

## Failure mode

Il controllo deve fallire quando l'adapter contiene valori canonici duplicati, associa uno schema di authoring a un registro persistente, invoca un percorso non governato oppure produce modifiche non deterministiche.
