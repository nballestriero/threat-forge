# MR-0002ADR-0004REQ-0003 — Contratto di authoring guidato dei requisiti governati

## Intento

Ridurre gli errori durante la creazione dei requisiti e impedire che identificativi, relazioni, valori controllati, record YAML e body Markdown vengano costruiti tramite input non verificati o logica duplicata.

## Obbligo funzionale

ThreatForge deve fornire un core locale di authoring dei requisiti governati indipendente dall'IDE.

Il core deve:

- leggere macro-requirement, decisioni, requisiti padre e tassonomie dalle rispettive fonti canoniche;
- distinguere categorie astratte e tipi concreti memorizzabili nel campo `requirement_type`;
- produrre un catalogo di authoring deterministico contenente identificativi selezionabili, valori ammessi, significati e regole applicabili;
- produrre uno JSON Schema derivato dal catalogo e dalle fonti canoniche;
- supportare la preview completa del record YAML e del body Markdown prima della scrittura;
- richiedere una conferma esplicita prima di applicare la creazione;
- creare atomicamente il record del registro e il body Markdown associato;
- eseguire immediatamente i controlli governati applicabili dopo la creazione.

Il core non deve dipendere da VS Code e deve poter essere utilizzato direttamente tramite CLI o da altri adapter locali.

## Ambito iniziale

Incluso:

- requisiti funzionali;
- requisiti di governance;
- selezione della macro-requirement;
- selezione dell'ADR applicabile;
- selezione del requisito padre quando richiesta dal tipo concreto;
- generazione deterministica di identificativo e `body_path`;
- preview priva di side effect;
- creazione confermata;
- controllo successivo alla creazione.

Escluso:

- introduzione di una custom extension VS Code;
- creazione iniziale di tipi concreti diversi da `functional` e `governance`;
- modifica automatica di decisioni o macro-requirement;
- commit o push automatici.

## Acceptance

Il requisito e soddisfatto quando, a parita di snapshot canonico, il core produce un catalogo e uno schema deterministici e consente di:

- selezionare soltanto macro-requirement, ADR e requisiti padre esistenti e applicabili;
- selezionare soltanto tipi concreti registrati nella tassonomia `requirement_type`;
- respingere `specialized` come valore concreto e come alias di `governance`;
- visualizzare record e body completi senza modificare il repository;
- creare record e body soltanto dopo conferma esplicita;
- lasciare entrambi gli artefatti invariati o assenti quando la creazione fallisce;
- eseguire i controlli applicabili e riportarne il risultato dopo una creazione riuscita.
