# MR-0002ADR-0003REQ-0002 — Promozione governata di uno scaffold implementativo

## Intento

Permettere di dichiarare completato uno scaffold soltanto dopo che il comportamento reale è stato scritto e verificato.

## Obbligo funzionale

ThreatForge deve selezionare uno scaffold tramite l'identificativo dell'artefatto nell'implementation trace registry e deve:

- accettare esclusivamente record nello stato `scaffolded`;
- risolvere dal registro path, requisito collegato e comando di verifica;
- verificare la coerenza delle dichiarazioni di tracciabilità del sorgente;
- rifiutare il placeholder generato dallo scaffolder e un file privo di comportamento implementativo;
- eseguire il comando di verifica governato senza usare una shell;
- sostituire `@implementationStatus scaffolded` con `@implementationStatus implemented`;
- sostituire atomicamente `status: scaffolded` e `scaffolded_path` con `status: implemented` e `implemented_path`;
- stampare identificativo, path, stato e verifica eseguita;
- rendere la capacità richiamabile da un task VS Code.

## Ambito

Incluso:

- artefatti sorgente creati dallo scaffolder governato;
- selezione tramite artifact ID;
- verifica `node --test`, `node --check` o gate canonico `node tools/repo-check.mjs`;
- aggiornamento atomico del sorgente e dell'implementation trace registry;
- conferma esplicita prima della promozione.

Escluso:

- scrittura autonoma del comportamento applicativo o dei test;
- promozione di record `planned`, `implemented`, `deprecated` o `superseded`;
- modifica di path o requisiti collegati;
- commit o push automatici;
- rimozione indiscriminata di TODO non generati dallo scaffolder.

## Acceptance

Il requisito è soddisfatto quando uno scaffold con comportamento reale e verifica riuscita viene promosso in modo atomico, il file e il registro dichiarano entrambi `implemented` e il `repo-check` passa immediatamente dopo la promozione.
