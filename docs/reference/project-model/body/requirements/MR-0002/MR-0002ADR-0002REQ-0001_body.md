# MR-0002ADR-0002REQ-0001 — Commit e push governati dalla root canonica

## Intent

Provide one local publication command that verifies the canonical repository before staging, committing and pushing intentional changes.

## Functional obligation

- ThreatForge must provide one repository-operation runner executable from the canonical repository root.
- The runner must execute repository gates without Git mutation in check mode.
- The runner must execute repository gates, staging, commit and push in that order in publication mode.
- The runner must accept the commit message as explicit input.
- The runner must display repository context, staged files and final synchronization state.
- The runner must stop at the first failed operation and return a non-zero exit code.
- The runner must refuse publication when the current branch has no configured upstream.
- The runner must include all non-ignored intentional workspace changes that remain after successful governed materialization and checks.

## Scope

- Includes: the canonical ThreatForge Git repository
- Includes: the current branch and configured upstream
- Includes: governed check and commit-push modes
- Includes: direct Node.js invocation
- Excludes: automatic commit-message selection
- Excludes: hook bypass, branch creation, remote changes and pull-request creation
- Excludes: mutation of archived legacy tooling

## Acceptance

- The requirement is accepted when check mode executes the governed gate without staging or committing.
- The requirement is accepted when publication mode completes gate, stage, commit and push in canonical order.
- The requirement is accepted when a failed gate prevents every later Git mutation.
- The requirement is accepted when the runner reports the staged paths and final branch synchronization state.
- The requirement is accepted when the commit message always originates from explicit author input.
