# MR-0002ADR-0002REQ-0001 — Commit e push governati dalla root canonica

## Intento

Fornire un unico comando locale che verifichi il progetto e pubblichi modifiche intenzionali senza saltare i gate canonici.

## Obbligo funzionale

ThreatForge deve fornire un runner CLI capace di:

- eseguire soltanto i gate in modalità di controllo;
- eseguire gate, stage, commit e push in modalità di pubblicazione;
- ricevere il messaggio di commit come input esplicito;
- mostrare contesto Git, file staged e stato finale;
- restituire codice di uscita non zero al primo errore.

## Ambito

Incluso:

- repository Git della root canonica;
- branch corrente con upstream configurato;
- tutte le modifiche non ignorate presenti al momento dell'esecuzione;
- invocazione diretta tramite Node.js.

Escluso:

- modifica dei tool del progetto legacy;
- scelta automatica del messaggio di commit;
- bypass degli hook Git;
- creazione o cambio automatico di branch e remote;
- apertura automatica di pull request.

## Acceptance

Il requisito è soddisfatto quando il runner può completare `repo-check`, stage, commit e push nell'ordine governato, oppure arrestarsi senza eseguire le operazioni successive quando un controllo fallisce.
