# MR-0002ADR-0002REQ-0001GOV-0002 — Controllo deterministico del runner di repository

## Intento

Rendere rilevabile ogni regressione che trasformi il runner in un percorso capace di saltare i gate o perdere la propria tracciabilità.

## Obbligo di governance

Un checker deterministico deve validare che il runner:

- esista nel path canonico;
- dichiari requisito, decisione e macro-requirement implementati;
- esponga le modalità `--check` e `--commit-push`;
- richiami il `repo-check` canonico;
- mantenga l'ordine gate, stage, controllo staged, commit e push;
- mantenga il controllo del messaggio e dell'upstream;
- sia coperto da fixture negative che rimuovono singole garanzie obbligatorie.

## Controlli minimi

- verifica statica della sorgente del runner;
- esecuzione di tutte le fixture negative registrate;
- fallimento della fixture quando la regressione attesa non viene rilevata;
- integrazione del checker nel `repo-check` locale.

## Failure mode

Il controllo deve fallire quando il runner è assente, perde tracciabilità, non richiama il gate canonico, modifica l'ordine governato o una fixture negativa non produce il diagnostico previsto.
