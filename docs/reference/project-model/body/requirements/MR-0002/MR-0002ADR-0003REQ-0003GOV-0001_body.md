# MR-0002ADR-0003REQ-0003GOV-0001 — Transizione verificata e atomica degli artefatti materializzati pianificati

## Intent

Impedire che un artefatto materializzato non sorgente venga dichiarato
implementato senza esistenza verificata, verifica governata riuscita
e aggiornamento coerente del relativo record di implementazione.

## Governance obligation

- The governed implementation must accept exactly one implementation artifact identifier.
- The governed implementation must accept only a record whose lifecycle status is planned.
- The governed implementation must require exactly one repository-relative planned path.
- The governed implementation must require the planned artifact file to exist without modifying its content.
- The governed implementation must execute only the registered governed Node verification command without invoking a shell.
- The governed implementation must require the exact explicit confirmation promote.
- The governed implementation must replace status planned with implemented.
- The governed implementation must replace planned path with the identical implemented path.
- The governed implementation must preserve artifact identifier artifact type linked Requirements and verification command.
- The governed implementation must update the implementation trace registry atomically with rollback on failure.
- The governed implementation must not perform commit or push operations.

## Verification obligations

- The verification must confirm rejection of unknown artifact identifiers.
- The verification must confirm rejection of scaffolded implemented deprecated and superseded records.
- The verification must confirm rejection when the planned path is missing unsafe or absent.
- The verification must confirm rejection when the registered verification command is unsupported or fails.
- The verification must confirm that failed promotion leaves the artifact and trace registry unchanged.
- The verification must confirm the final implemented status and implemented path.
- The verification must confirm preservation of identifier artifact type linked Requirements path and verification command.
- The verification must confirm that the materialized artifact bytes remain unchanged.
- The verification must confirm removal of every temporary transaction file after success or rollback.

## Failure conditions

- The verification must fail when the implementation artifact identifier is missing invalid unknown or ambiguous.
- The verification must fail when the selected implementation trace record is not planned.
- The verification must fail when the planned path is missing unsafe or does not resolve to an existing file.
- The verification must fail when the verification command is missing unsupported or unsuccessful.
- The verification must fail when explicit confirmation promote is not provided.
- The verification must fail when the artifact content changes during promotion.
- The verification must fail when the final trace record does not declare implemented status and implemented path.
- The verification must fail when any preserved trace field changes unexpectedly.
- The verification must fail when a failed operation leaves a persistent registry mutation or temporary transaction file.
