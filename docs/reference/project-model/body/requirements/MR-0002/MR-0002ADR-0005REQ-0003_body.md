# MR-0002ADR-0005REQ-0003 — Editor VS Code guidato per MR, ADR e REQ

## Intent

Provide guided governed-document authoring in Visual Studio Code with immediate suggestions, descriptions and validation before repository mutation.

## Functional obligation

- VS Code must recognize governed request files for Macro-requirement, ADR, Functional Requirement and Governance Requirement authoring.
- The editor integration must propose only fields applicable to the selected document type.
- The editor integration must propose only controlled values applicable to the selected field and context.
- Completion items must display canonical labels and descriptions.
- Hover information must expose the canonical description of fields and values.
- Editor diagnostics must identify invalid values, incoherent relations and missing required fields.
- Relation fields must propose existing canonical identifiers applicable to the current context.
- The workspace must expose governed preview and confirmed-application tasks.
- The editor adapter must invoke the shared authoring core without duplicating domain rules.
- Regenerated canonical projections must update editor proposals after source changes.

## Scope

- Includes: governed authoring request files
- Includes: completion, hover and diagnostics
- Includes: MR, ADR and REQ relation suggestions
- Includes: preview and confirmed application tasks
- Excludes: direct schema association with canonical registries
- Excludes: manual editing of generated identifiers or derived relations
- Excludes: editor-owned copies of canonical domain rules

## Acceptance

- The requirement is accepted when an author can create an MR, ADR or REQ request in VS Code.
- The requirement is accepted when controlled values receive context-specific completion.
- The requirement is accepted when completion and hover expose canonical descriptions.
- The requirement is accepted when diagnostics appear before tool execution.
- The requirement is accepted when preview has no repository side effects.
- The requirement is accepted when application requires explicit confirmation.
- The requirement is accepted when resulting records and bodies are coherent and verified.
- The requirement is accepted when regenerated projections refresh editor proposals deterministically.
