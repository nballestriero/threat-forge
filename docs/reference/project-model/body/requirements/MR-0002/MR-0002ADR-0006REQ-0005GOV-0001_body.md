# MR-0002ADR-0006REQ-0005GOV-0001 — Deterministic workspace routing and single-provider migration

## Intent

Ensure that the unified VS Code extension selects the correct assistance composition deterministically and replaces the former competing extension packages without duplicating canonical rules.

## Governance obligation

- The unified adapter must derive workspace mode independently for each VS Code workspace folder.
- A workspace folder must be classified as a Target Project only when threatforge.engineRoot is explicitly defined at workspace-folder scope.
- A user-level or globally inherited threatforge.engineRoot value must not classify a workspace as a Target Project.
- A workspace folder must be classified as the ThreatForge engine only when the required engine-owned assistance modules are present beneath that folder.
- Target Project classification must take precedence over engine classification when a valid workspace-folder engine root is explicitly declared.
- Unsupported workspace folders must produce no ThreatForge diagnostic, completion, hover or quick fix.
- The unified extension must register one provider set rather than separate engine and Target Project provider sets.
- The unified adapter must delegate engine analysis to the shared governed Markdown assistance core.
- The unified adapter must delegate Target Project analysis to the Target Project assistance composition root.
- The unified adapter must not contain canonical section inventories, controlled value sets or governed-reference taxonomies.
- The Target Project workspace materializer must recommend only the unified ThreatForge Markdown assistance extension.
- The unified installer must replace the obsolete Target Project assistance extension during migration.
- The migration must preserve target-local documents, Base Analysis records and canonical ThreatForge sources.

## Verification obligations

- The verification must exercise engine mode against a registered ThreatForge governed Markdown body.
- The verification must exercise Target Project mode with an absolute engine root.
- The verification must exercise the repository-contained Target Project with a relative engine root.
- The verification must confirm that an unsupported Markdown workspace is ignored without diagnostics.
- The verification must confirm that the ThreatForge engine workspace produces no missing target engine-root diagnostic.
- The verification must confirm that a globally inherited engine-root setting does not override workspace classification.
- The verification must confirm that only one completion provider result set is exposed for one governed document.
- The verification must compare canonical section and controlled-value completions across engine and Target Project modes.
- The verification must confirm that Target Project BAE completions are resolved only from the target-local inventory.
- The verification must inspect the unified adapter for duplicated canonical headings and controlled values.
- The verification must confirm that generated Target Project extension recommendations contain the unified extension identifier and exclude the obsolete identifier.
- The verification must confirm that the installation workflow removes the obsolete Target Project extension and installs the unified package.

## Failure conditions

- The verification must fail when two ThreatForge extension packages register competing Markdown providers.
- The verification must fail when an engine workspace is interpreted as a Target Project.
- The verification must fail when an unsupported workspace receives a ThreatForge analysis error.
- The verification must fail when a global engine-root setting classifies an unrelated workspace as a Target Project.
- The verification must fail when engine and Target Project modes return different canonical section ordering for equivalent governed documents.
- The verification must fail when the Target Project materializer recommends the obsolete extension identifier.
- The verification must fail when migration modifies governed Markdown bodies or canonical Base Analysis records.
