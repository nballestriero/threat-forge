# MR-0002ADR-0005REQ-0002GOV-0001 — Adapter VS Code sottile e privo di regole canoniche duplicate

## Intento

Garantire che l'integrazione VS Code rimanga un adapter locale del core governato e non diventi una seconda fonte delle regole di authoring.

## Obbligo di governance

La configurazione VS Code deve:

- invocare esclusivamente entry point CLI governati;
- usare label visibili con prefisso `ThreatForge:`;
- eseguire i comandi dalla root del repository;
- mantenere separati preview e creazione confermata;
- lasciare al core la selezione dinamica dei valori canonici;
- lasciare al core preview, conferma, scrittura atomica e controlli successivi;
- associare ai documenti YAML `*.requirement-authoring.yml` soltanto uno schema generato dal core;
- non associare lo schema di richiesta authoring ai registri YAML canonici;
- utilizzare snippet generati o verificati rispetto al contratto canonico;
- non contenere liste statiche di MR, ADR, requisiti padre, status o tipi di requisito;
- non introdurre una custom extension.

Il valore predefinito di ogni conferma deve essere non distruttivo.

Non deve esistere un task che bypassi la preview o trasformi una semplice selezione dalla palette in una scrittura incondizionata.

I registri YAML canonici e i body governati devono essere modificati esclusivamente dal core dopo preview e conferma esplicita.

## Controlli minimi

Deve essere possibile verificare deterministicamente che:

- ogni task richiami un comando governato esistente;
- il `cwd` sia `${workspaceFolder}`;
- le label rispettino il prefisso canonico;
- il task di preview non abiliti la scrittura;
- il task di creazione non contenga opzioni di conferma automatica;
- i file `.vscode` non contengano enum canonici duplicati;
- lo schema associato sia quello prodotto dal core;
- l'associazione dello schema riguardi `*.requirement-authoring.yml` e non i registri YAML canonici;
- gli snippet siano coerenti con i template governati.

## Failure mode

Il controllo deve fallire quando la configurazione VS Code duplica valori canonici, contiene logica di validazione, abilita una scrittura non confermata, richiama un comando non governato, associa uno schema non derivato dal core oppure applica lo schema di richiesta authoring ai registri YAML canonici.
