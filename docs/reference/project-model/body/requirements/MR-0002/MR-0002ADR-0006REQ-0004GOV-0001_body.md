# MR-0002ADR-0006REQ-0004GOV-0001 — Canonical reference ranking and thin adapter equivalence

## Intent

Ensure deterministic governed reference assistance derived exclusively from canonical document, resolver and entity projections.

## Governance obligation

- The Markdown assistance core must derive reference syntax from MR-0001 canonical reference contracts.
- The Markdown assistance core must derive reference-bearing positions from canonical body profiles.
- The Markdown assistance core must derive candidate identities and titles from registered governed entity resolvers.
- The Markdown assistance core must derive candidate eligibility from entity-owning models.
- The Markdown assistance core must derive BAE meaning, origin, provenance and lifecycle metadata from MR-0003 canonical projections.
- The first completion ranking group must contain eligible identifiers already referenced in the current unsaved body.
- The first completion ranking group must order identifiers by last textual occurrence in descending order.
- Equal last-occurrence positions must be ordered by canonical identifier.
- The second completion ranking group must contain remaining eligible identifiers related to the current governed document.
- The second completion ranking group must be ordered by canonical identifier.
- The third completion ranking group must contain all remaining eligible identifiers.
- The third completion ranking group must be ordered by canonical identifier.
- Completion ranking must preserve the first applicable group for every identifier.
- Completion results must be deterministic for identical canonical inputs and unsaved text.
- Hover results must be deterministic for identical canonical inputs and cursor position.
- Diagnostic and quick-fix results must use canonical stable rule identifiers.
- VS Code and web editor adapters must consume the same shared assistance result.
- An editor adapter must not duplicate reference grammar, resolver, eligibility or ranking rules.
- An editor adapter must not introduce compatibility aliases for alternative reference forms.
- The assistance core and editor adapters must not mutate canonical entities or governed documents.

## Verification obligations

- The verification must compare completion payloads with MR-0001 canonical serialization.
- The verification must compare candidate identities and titles with registered resolver output.
- The verification must compare BAE hover metadata with MR-0003 canonical projections.
- The verification must confirm the three completion ranking groups and their internal ordering.
- The verification must confirm deduplication when one identifier belongs to multiple ranking groups.
- The verification must compare repeated completion, hover, diagnostic and quick-fix results for deterministic equivalence.
- The verification must compare VS Code and web editor semantic results for identical analysis input.
- The verification must cover canonical, noncanonical, unknown, ambiguous, disallowed, title-divergent and ineligible reference fixtures.
- The verification must cover repeated identifiers and equal-ranking tie fixtures.
- The verification must confirm that assistance leaves documents, registries and canonical entity sources unchanged.

## Failure conditions

- The verification must fail when a completion payload diverges from canonical serialization.
- The verification must fail when a completion title diverges from its authoritative entity title.
- The verification must fail when an ineligible entity appears in completion results.
- The verification must fail when an identifier already used in the current body is ranked below an unused identifier.
- The verification must fail when document-related identifiers are ranked below remaining eligible identifiers.
- The verification must fail when one identifier appears more than once in a completion result.
- The verification must fail when identical input produces different semantic ordering.
- The verification must fail when editor adapters produce different semantic results.
- The verification must fail when an adapter contains independent reference or ranking rules.
- The verification must fail when assistance modifies a document, registry or canonical entity source.
