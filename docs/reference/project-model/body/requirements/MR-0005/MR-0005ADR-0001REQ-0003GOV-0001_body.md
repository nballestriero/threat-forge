# MR-0005ADR-0001REQ-0003GOV-0001 — Human-viewable DFD renderer validation

## Intent

Ensure that human-viewable DFD rendering remains deterministic, complete, traceable and isolated from canonical semantic records.

## Governance obligation

- The renderer must accept only a valid renderer-neutral DFD semantic projection.
- The renderer must produce deterministic output for identical semantic projections.
- The renderer must represent every projected node, directed data flow and boundary exactly once.
- The renderer must preserve projection, BAE and relation traceability identities in accessible artifact metadata.
- The renderer must keep layout and presentation information outside the semantic projection.
- The renderer must leave the input projection, canonical BAE registries and governed analysis records unchanged.
- The initial rendering adapter must produce a self-contained static HTML artifact containing an embedded SVG.
- The renderer must safely encode projection-provided text before inserting it into HTML or SVG.

## Verification obligations

- The verification must render the canonical Base DFD case-study projection.
- The verification must compare repeated renderings byte for byte.
- The verification must confirm representation of every projected node, directed data flow and boundary.
- The verification must confirm access to projection, BAE and relation traceability identities.
- The verification must confirm that rendering does not mutate its semantic input or canonical sources.
- The verification must confirm that layout and presentation information remains absent from the semantic projection.
- The verification must confirm safe HTML and SVG encoding of projection-provided text.
- The verification must include deterministic positive and negative fixtures.

## Failure conditions

- The verification must fail when a projected node, directed data flow or boundary is omitted or duplicated.
- The verification must fail when repeated rendering of the same semantic projection produces different output.
- The verification must fail when projection, BAE or relation traceability identities are absent from the artifact.
- The verification must fail when rendering mutates the semantic projection or canonical governed records.
- The verification must fail when renderer-specific layout or presentation data is written into the semantic projection.
- The verification must fail when the generated artifact depends on an external runtime or network resource.
- The verification must fail when projection-provided text is inserted without safe HTML and SVG encoding.
