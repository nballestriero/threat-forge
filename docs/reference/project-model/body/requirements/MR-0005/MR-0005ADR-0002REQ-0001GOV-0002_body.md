# MR-0005ADR-0002REQ-0001GOV-0002 — Deterministic common finding editor schema materialization

## Intent

Make common finding YAML editor assistance deterministic, model-derived and verifiably synchronized with the canonical analysis-domain profile.

## Governance obligation

- The canonical common finding representation profile must materialize one deterministic machine-readable JSON Schema for YAML editor assistance.
- The materialized editor schema must expose canonical fields identifier constraints controlled review states affected-subject kinds and field descriptions without defining independent model rules.
- Schema materialization must derive exclusively from the canonical common finding model and representation profile.
- The schema materializer must support explicit write and check modes.
- Write mode must create or update only the common finding editor schema through an atomic file replacement.
- Check mode must fail when the materialized schema is missing invalid or stale.
- Repeated materialization from identical canonical inputs must produce equivalent repository-stable output.
- Schema materialization must not modify common findings analysis records Base Analysis records relations Functional Requirements or governed source registries.
- Implementation traces must link the schema materializer materialized schema and verification suite to this Governance Requirement.

## Verification obligations

- The verification must compare repeated common finding editor schema materializations for deterministic equivalence.
- The verification must confirm that the schema exposes canonical properties identifier constraints controlled values field descriptions and ThreatForge metadata.
- The verification must confirm that write mode creates updates or preserves the schema deterministically.
- The verification must confirm that check mode accepts a current schema and rejects a missing invalid or stale schema.
- The verification must confirm that schema materialization leaves every canonical governed source unchanged.
- The verification must confirm implementation traceability for the materializer schema and verification suite.

## Failure conditions

- The verification must fail when the canonical common finding model or representation profile is missing or inconsistent.
- The verification must fail when repeated materialization from identical canonical inputs produces different output.
- The verification must fail when check mode accepts a missing invalid or stale materialized schema.
- The verification must fail when the materialized schema diverges from the canonical common finding model or defines independent model rules.
- The verification must fail when schema materialization modifies a common finding analysis record Base Analysis record relation Functional Requirement or governed source registry.
- The verification must fail when implementation traceability for the schema materializer materialized schema or verification suite is missing.
