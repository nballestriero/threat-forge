# MR-0005ADR-0001REQ-0004GOV-0001 — Deterministic methodology-specific analysis record model and identity validation

## Intent

Make malformed or incoherent methodology-specific analysis record
identities, method ownership, analysis scopes, governed subject references,
derivation acceptance indicators and downstream finding origins
deterministically detectable through stable diagnostics.

## Governance obligation

- Methodology-specific analysis record validation must consume the canonical analysis-domain record model its representation profile and the governed entity reference grammar.
- The methodology-specific analysis record model must remain outside the governed document model registry and governed document authoring catalog.
- Every analysis record diagnostic rule must have a stable canonical identifier.
- Analysis record validation must enforce the deterministic identifier syntax declared by the canonical analysis record model.
- Analysis record validation must reject duplicate canonical analysis record identifiers.
- Every methodology-specific analysis record must identify exactly one selected analysis method.
- Every methodology-specific analysis record must record one non-empty contributing analyst identity without certifying that identity.
- Every methodology-specific analysis record must define a non-empty analysis scope.
- Every methodology-specific analysis record must contain one or more governed analysis subject references.
- Governed analysis subjects must be limited to Base Analysis Elements Base Analysis relations or governed Functional Requirements.
- Every governed analysis subject reference must resolve through the canonical model that owns its identity.
- Every methodology-specific analysis record must explicitly expose the model-declared acceptance indicator for deterministic derivation.
- Validation and transformation logic must not infer or assign derivation acceptance from method classifications evidence or affected references.
- Method-specific classifications must remain owned by the selected analysis method.
- Method-specific classifications must not become universal fields of the common analysis record profile.
- Validation and materialization must not modify canonical Base Analysis records Base Analysis relations or governed Functional Requirements.
- A downstream common finding origin reference must resolve one canonical methodology-specific analysis record identity.
- The canonical analysis record profile must materialize one deterministic machine-readable schema for YAML editor assistance.
- The materialized editor schema must expose canonical fields identifier constraints controlled values and field descriptions without defining independent model rules.
- Analysis record negative fixtures must declare the stable rule identifiers they expect to trigger.
- Implementation traces must link the model validator schema materializer fixtures and verification suites to this Governance Requirement.

## Verification obligations

- The verification must accept one canonical methodology-specific analysis record model and representation profile.
- The verification must confirm that the analysis record model is not registered as a governed document model or authorable governed document type.
- The verification must accept a valid record with one stable identifier one selected method one contributing analyst one scope and one governed analysis subject.
- The verification must cover Base Analysis Element Base Analysis relation and governed Functional Requirement subject references.
- The verification must confirm that accepted and not accepted derivation states are explicitly distinguishable according to the canonical model.
- The verification must confirm that derivation acceptance is never inferred or assigned automatically.
- The verification must confirm that method-specific classifications remain owned by the selected analysis method.
- The verification must confirm that validation and materialization leave governed source records unchanged.
- The verification must confirm that a common finding can resolve one originating analysis record identity.
- The verification must compare repeated editor schema materializations for deterministic equivalence.
- The verification must confirm that the editor schema exposes canonical properties constraints controlled values and descriptions.
- The verification must confirm that every emitted diagnostic contains a known stable rule identifier.
- The verification must confirm that negative fixtures trigger every declared rule identifier.
- The verification must reject duplicate analysis record diagnostic rule identifiers.

## Failure conditions

- The verification must fail when the canonical methodology-specific analysis record model or representation profile is missing or inconsistent.
- The verification must fail when the analysis record model is registered as a governed document model or authorable governed document type.
- The verification must fail when an analysis record identifier is missing malformed duplicated or not resolvable.
- The verification must fail when an analysis record identifies zero or more than one selected analysis method.
- The verification must fail when an analysis record omits its contributing analyst identity.
- The verification must fail when an analysis record omits its analysis scope.
- The verification must fail when an analysis record contains no governed analysis subject reference.
- The verification must fail when an analysis subject uses an unsupported kind or does not resolve through its owning canonical model.
- The verification must fail when an analysis record omits or violates the model-declared derivation acceptance indicator.
- The verification must fail when validation or transformation logic infers or assigns derivation acceptance automatically.
- The verification must fail when method-specific classifications are promoted into universal fields of the common analysis record profile.
- The verification must fail when validation or materialization modifies a canonical Base Analysis record Base Analysis relation or governed Functional Requirement.
- The verification must fail when a downstream common finding origin does not resolve exactly one canonical analysis record.
- The verification must fail when repeated editor schema materialization from identical canonical inputs produces different output.
- The verification must fail when the materialized editor schema diverges from the canonical analysis record model or defines independent model rules.
- The verification must fail when an emitted diagnostic omits a stable rule identifier.
- The verification must fail when a negative fixture does not trigger every rule identifier it declares.
- The verification must fail when implementation traceability for the model validator schema materializer fixtures or verification suites is missing.
