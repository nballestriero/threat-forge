# MR-0005ADR-0004REQ-0001GOV-0001 — Deterministic Common Finding reference model verification

## Intent

Ensure that the Common Finding canonical title, repository-derived source projection, resolver registration and accepted-state eligibility are implemented and verified through deterministic model-derived controls.

## Governance obligation

- The canonical Common Finding model must declare title as a required field.
- The canonical Common Finding profile must describe title as non-empty single-line authored text.
- The Common Finding canonicalizer must preserve the authored title unchanged.
- The Common Finding canonicalizer must not synthesize a missing title.
- The Common Finding validator must reject a missing empty or multiline title.
- The Common Finding editor schema must derive the title constraint from canonical model metadata.
- The Common Finding source projection provider must derive its entries from repository-discovered validated Finding records.
- The Common Finding source projection provider must preserve identifier title review state and repository-relative source path.
- The Common Finding source projection provider must not maintain an independent Finding inventory.
- The Common Finding identity index must preserve duplicate identifiers as ambiguous.
- The governed entity resolver registry must contain exactly one active common_analysis_finding resolver.
- The common_analysis_finding resolver must use the canonical FINDING identifier pattern.
- The Common Finding eligibility provider must accept an accepted Finding in an authorized Security Requirement reference position.
- The Common Finding eligibility provider must reject proposed and rejected Findings in Security Requirement reference positions.
- The governed reference checker must reject a title that diverges from the canonical Finding title.
- Common Finding reference resolution must leave every authored Finding record unchanged.
- Every implementation artifact must declare MR-0005ADR-0004REQ-0001GOV-0001 in its implementation trace.

## Verification obligations

- The verification must accept a canonical Finding with a valid title.
- The verification must reject missing empty and multiline titles.
- The verification must prove that canonicalization neither synthesizes nor mutates titles.
- The verification must prove deterministic editor schema materialization.
- The verification must prove that only validated discovered Findings enter the source projection.
- The verification must prove that duplicate Finding identifiers do not resolve.
- The verification must prove that exactly one active common_analysis_finding resolver is registered.
- The verification must prove that an accepted Finding is eligible in an authorized Security Requirement position.
- The verification must prove that proposed and rejected Findings are ineligible in Security Requirement positions.
- The verification must prove that governed reference titles match canonical Finding titles.
- The verification must prove that reference processing leaves authored Finding sources unchanged.
- The verification must execute the Common Finding model reference and eligibility suites through the repository gate.

## Failure conditions

- The verification must fail when a Common Finding omits title.
- The verification must fail when a Common Finding title is empty or contains a line break.
- The verification must fail when canonicalization fabricates or changes a Finding title.
- The verification must fail when the editor schema diverges from canonical title metadata.
- The verification must fail when an invalid or undiscovered Finding enters the source projection.
- The verification must fail when the source projection diverges from the validated discovered Finding set.
- The verification must fail when duplicate Finding identifiers resolve as one entity.
- The verification must fail when the active common_analysis_finding resolver is missing or duplicated.
- The verification must fail when the resolver identifier pattern differs from the canonical Finding pattern.
- The verification must fail when an accepted Finding is rejected in an authorized Security Requirement position.
- The verification must fail when a proposed or rejected Finding is accepted in a Security Requirement position.
- The verification must fail when a governed reference title diverges from the canonical Finding title.
- The verification must fail when reference processing modifies an authored Finding source.
- The verification must fail when an implementation artifact lacks the required traceability declaration.
