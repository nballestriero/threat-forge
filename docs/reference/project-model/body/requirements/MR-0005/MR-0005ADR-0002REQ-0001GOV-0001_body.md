# MR-0005ADR-0002REQ-0001GOV-0001 — Deterministic common finding model and review-state validation

## Intent

Make malformed or incoherent common finding identities, analytical
origins, affected references, review states and security derivation
boundaries deterministically detectable through stable diagnostics.

## Governance obligation

- Common finding validation must consume the canonical analysis-domain finding model record profile governed reference grammar and controlled review-state values.
- The common finding model must remain outside the governed document model registry and governed document authoring catalog.
- Every common finding diagnostic rule must have a stable canonical identifier.
- Common finding validation must enforce the identifier syntax declared by the canonical finding model.
- Common finding validation must require exactly one originating governed analysis record.
- The originating governed analysis reference must resolve through its owning canonical model.
- Every common finding must contain at least one affected Base Analysis Element relation or governed Functional Requirement reference.
- Every affected governed entity reference must resolve through its owning canonical model.
- A common finding in the accepted state must reference at least one governed Functional Requirement.
- Common finding validation must require one concrete threat scenario.
- Common finding validation must require expected consequences.
- Common finding validation must require supporting rationale or evidence.
- Common finding validation must restrict the review state to proposed accepted or rejected.
- Finding review state must be explicitly recorded.
- Validation and transformation logic must not infer or assign the accepted state automatically from finding content governed references shared consequences or method-specific data.
- Common finding validation must reject method-specific classifications applicability rules failure modes and attack classes in the common record.
- Shared subjects consequences or governed references must not establish automatic finding identity equivalence or consolidation.
- Common finding negative fixtures must declare the stable rule identifiers they expect to trigger.

## Verification obligations

- The verification must confirm that one canonical analysis-domain common finding model and its representation profile are accepted.
- The verification must confirm that the common finding model is not registered as a governed document model or authorable governed document type.
- The verification must confirm that a valid proposed finding resolves one originating analysis and at least one affected governed reference.
- The verification must confirm that a valid accepted finding resolves at least one affected governed Functional Requirement.
- The verification must confirm that proposed accepted and rejected are the only accepted review states.
- The verification must confirm that finding review state is explicitly recorded.
- The verification must confirm that the accepted state is never inferred or assigned automatically.
- The verification must confirm that threat scenario consequences and supporting rationale or evidence are required.
- The verification must confirm that method-specific interpretation fields are rejected from the common finding record.
- The verification must confirm that shared references do not automatically merge or equate independent findings.
- The verification must confirm that every diagnostic contains a known stable rule identifier.
- The verification must confirm that negative fixtures trigger every declared rule identifier.
- The verification must reject duplicate common finding rule identifiers.

## Failure conditions

- The verification must fail when the canonical analysis-domain common finding model or representation profile is missing inconsistent or references an unknown canonical source.
- The verification must fail when the common finding model is registered as a governed document model or authorable governed document type.
- The verification must fail when a common finding identifier violates the syntax declared by the canonical finding model.
- The verification must fail when an originating analysis reference is missing duplicated or unresolved.
- The verification must fail when a common finding contains no affected governed entity reference.
- The verification must fail when an affected Base Analysis Element relation or Functional Requirement reference is unresolved.
- The verification must fail when an accepted finding does not reference at least one governed Functional Requirement.
- The verification must fail when a common finding omits its concrete threat scenario.
- The verification must fail when a common finding omits expected consequences.
- The verification must fail when a common finding omits supporting rationale or evidence.
- The verification must fail when a common finding uses a review state other than proposed accepted or rejected.
- The verification must fail when a common finding omits its explicitly recorded review state.
- The verification must fail when validation or transformation logic infers or assigns the accepted state automatically.
- The verification must fail when a common finding record contains method-specific classifications applicability rules failure modes or attack classes.
- The verification must fail when independent findings are automatically merged or treated as equivalent because they share references or consequences.
- The verification must fail when an emitted diagnostic omits a stable rule identifier.
- The verification must fail when a negative fixture does not trigger every rule identifier it declares.
