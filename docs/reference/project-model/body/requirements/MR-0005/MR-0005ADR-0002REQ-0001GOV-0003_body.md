# MR-0005ADR-0002REQ-0001GOV-0003 — Repository-contained Common Finding case-study validation

## Intent

Demonstrate that manually authored methodology-specific analysis evidence can be validated as methodology-neutral Common Findings in the repository-contained Target Project case study without implementing a STRIDE plugin or Security Requirement derivation.

## Governance obligation

- The case study must contain one manually authored methodology-specific Analysis Record whose method_id is stride and whose method_payload is explicitly simulated evidence.
- The simulation must not claim that a STRIDE plugin analysis engine or automatic Finding derivation is implemented.
- STRIDE-specific classification data must remain confined to the Analysis Record method_payload.
- The case study must contain manually authored proposed accepted and rejected Common Findings.
- Every Common Finding must resolve its originating Analysis Record and affected Target Project subjects.
- The accepted Common Finding must reference the existing Target Project Functional Requirement.
- Finding review states must remain explicit.
- Finding review states must not be inferred from the simulated method payload.
- The case-study verification must compose engine-owned canonical rules with target-owned governed sources without copying engine rules into the Target Project.
- The simulation must not create or imply a Security Requirement.

## Verification obligations

- The verification must accept exactly one simulated Analysis Record.
- The verification must accept one proposed one accepted and one rejected Common Finding.
- The verification must confirm that all Base Analysis Element relation and Functional Requirement references resolve.
- The verification must confirm that STRIDE-specific fields occur only inside the Analysis Record method_payload.
- The verification must confirm that the accepted state is explicitly authored rather than inferred.
- The verification must produce deterministic evidence showing the Analysis Record Finding identities review states and governed references.
- The verification must confirm that the complete repository gate and Target Project validation remain successful.

## Failure conditions

- The verification must fail when The simulation requires or claims an implemented STRIDE plugin.
- The verification must fail when A Common Finding contains STRIDE-specific classification fields.
- The verification must fail when An originating Analysis Record or affected governed subject does not resolve.
- The verification must fail when A Finding review state is inferred or omitted.
- The verification must fail when An accepted Finding does not reference a Functional Requirement.
- The verification must fail when The simulation creates or implies a Security Requirement.
