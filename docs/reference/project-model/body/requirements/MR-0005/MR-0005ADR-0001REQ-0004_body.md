# MR-0005ADR-0001REQ-0004 — Canonical methodology-specific analysis record model and identity

## Intent

Provide a stable common identity and minimum canonical record boundary for
governed applications of analysis methods so downstream findings and
deterministic derivations can reference one originating analysis without
absorbing method-specific interpretation semantics.

## Functional obligation

- ThreatForge must define a canonical methodology-specific analysis record model.
- The canonical analysis record model must declare one deterministic identifier syntax.
- Every methodology-specific analysis record must have one stable canonical identifier.
- Every methodology-specific analysis record must be resolvable through its canonical identifier.
- Every methodology-specific analysis record must identify exactly one selected analysis method.
- Every methodology-specific analysis record must record one contributing analyst identity.
- Every methodology-specific analysis record must define its analysis scope.
- Every methodology-specific analysis record must reference one or more governed analysis subjects selected from Base Analysis Elements Base Analysis relations or governed Functional Requirements.
- Every governed analysis subject reference must preserve the canonical identity owned by its source model.
- Every methodology-specific analysis record must expose whether it is accepted for deterministic derivation.
- Methodology-specific classifications must remain owned by the selected analysis method.
- Methodology-specific analysis records must remain separate from the canonical Base Analysis registry.
- Creating or updating a methodology-specific analysis record must not modify canonical Base Analysis records or governed Functional Requirements.
- Downstream common findings must be able to preserve the canonical identity of their originating analysis record.

## Scope

- Includes: Canonical methodology-specific analysis record identity
- Includes: Deterministic analysis record identifier syntax
- Includes: Canonical record resolution boundary
- Includes: Selected analysis method identity
- Includes: Recorded contributing analyst identity
- Includes: Analysis scope
- Includes: Governed Base Analysis Element relation and Functional Requirement references
- Includes: Acceptance indicator for deterministic derivation
- Includes: Method-owned interpretation boundary
- Includes: Origin reference boundary for common findings
- Excludes: Certification of contributing analyst identity
- Excludes: Method-specific taxonomy definitions
- Excludes: Method-specific classification rules
- Excludes: Common finding record implementation
- Excludes: Documentation gap record implementation
- Excludes: Reviewer identity or evidence of human participation
- Excludes: Authorization and transition audit workflows
- Excludes: Quantitative risk scoring
- Excludes: Concrete STRIDE or STRIDE-AI analysis records

## Acceptance

- The requirement is accepted when the canonical analysis record model declares one deterministic identifier syntax.
- The requirement is accepted when every analysis record has a stable identifier resolvable through the canonical model.
- The requirement is accepted when every analysis record identifies exactly one selected method.
- The requirement is accepted when every analysis record records one contributing analyst identity without certifying that identity.
- The requirement is accepted when every analysis record defines its analysis scope.
- The requirement is accepted when every analysis record resolves one or more governed Base Analysis Element relation or Functional Requirement references.
- The requirement is accepted when records accepted for deterministic derivation are distinguishable from records not accepted.
- The requirement is accepted when method-specific classifications remain owned by the selected method.
- The requirement is accepted when analysis records remain outside the canonical Base Analysis registry.
- The requirement is accepted when analysis record operations leave canonical Base Analysis records and governed Functional Requirements unchanged.
- The requirement is accepted when a downstream common finding can preserve one originating analysis record identity.
