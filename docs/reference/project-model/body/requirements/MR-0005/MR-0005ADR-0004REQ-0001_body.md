# MR-0005ADR-0004REQ-0001 — Referenceable Common Finding identity and eligibility

## Intent

Make validated Common Findings consumable through the shared governed entity reference boundary while preserving their repository-contained source model and explicit review lifecycle.

## Functional obligation

- Every Common Finding must declare one canonical title.
- The Common Finding title must be a non-empty single-line human-readable value.
- The Common Finding title must remain distinct from the threat scenario.
- The Common Finding title must not be inferred from the threat scenario consequences rationale evidence method-specific data source path or file name.
- Common Finding discovery must continue to select repository-contained files through the existing .analysis-finding.yml discovery boundary.
- A Common Finding must enter the reference source projection only after its canonical record validates successfully.
- The Common Finding reference source projection must preserve the canonical identifier title explicit review state and repository-relative source path.
- Duplicate Common Finding identifiers must remain ambiguous.
- Duplicate Common Finding identifiers must not resolve as one canonical entity.
- The governed entity resolver registry must register at most one active resolver for the common_analysis_finding entity type.
- The Common Finding resolver must use the canonical FINDING identifier pattern.
- The Common Finding eligibility provider must permit references from Security Requirement positions only when review_state is accepted.
- Proposed and rejected Common Findings must remain canonical and resolvable.
- Proposed and rejected Common Findings must be ineligible in Security Requirement positions.
- Canonical Common Finding reference payloads must use the shared governed reference grammar.
- Resolving or referencing a Common Finding must not modify its title review state content or source file.
- ThreatForge must not create an independent Common Finding inventory for reference resolution.

## Scope

- Includes: Canonical Common Finding title
- Includes: Repository-derived validated Finding source projection
- Includes: Common Finding governed entity resolver registration
- Includes: Accepted-state Security Requirement eligibility
- Includes: Proposed and rejected Finding ineligibility
- Includes: Duplicate identifier ambiguity
- Includes: Shared canonical reference serialization
- Excludes: Security Requirement document model
- Excludes: Security Requirement body profile
- Excludes: STRIDE or STRIDE-AI methodology rules
- Excludes: Common Finding review workflow or transition authorization
- Excludes: Automatic Finding acceptance merge or deduplication
- Excludes: Central Common Finding registry
- Excludes: Changes to the existing Finding discovery root or ignored-directory policy

## Acceptance

- The requirement is accepted when every valid Common Finding contains an explicit canonical title.
- The requirement is accepted when a valid discovered Finding projects its identifier title review state and source path without mutation.
- The requirement is accepted when duplicate Finding identifiers do not resolve as one canonical entity.
- The requirement is accepted when an accepted Finding is eligible in a Security Requirement reference position.
- The requirement is accepted when proposed and rejected Findings are ineligible in a Security Requirement reference position.
- The requirement is accepted when the canonical payload serializes as a shared governed entity reference.
- The requirement is accepted when reference resolution does not create a separate Finding inventory or modify authored Finding sources.
