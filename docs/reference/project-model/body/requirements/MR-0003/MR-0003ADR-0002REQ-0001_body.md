# MR-0003ADR-0002REQ-0001 — BAE source continuity and reference occurrence projection

## Intent

Preserve the complete historical and current documentary authority of every Base Analysis Element and keep every governed usage synchronized without conflating manually governed identity, origin, provenance and derived textual references.

## Functional obligation

- Each BAE must be created manually in the canonical BAE registry before any governed document can cite it.
- Each manually created BAE must declare its stable identity, canonical title, base type, meaning and lifecycle state.
- Each BAE must preserve one immutable historical origin.
- Each BAE must expose one current authoritative source.
- Each BAE must expose an ordered append-only source history.
- The first source-history entry must identify the same governed source as the historical origin.
- The terminal source-history entry must identify the same governed source as the current authoritative source.
- Each source-history transition must identify its previous source, next source and governed review evidence.
- Source-history transitions must represent continuity confirmation, authority transfer, BAE supersession or BAE deprecation.
- A governed-document origin must contain one eligible introductory canonical citation of the registered BAE.
- The introductory citation must use the ordinary canonical reference syntax in a profile-declared reference position.
- The introductory citation must also appear in the derived reference occurrence projection.
- The Base Analysis capability must derive every BAE reference occurrence from governed Markdown bodies.
- A reference occurrence must identify the BAE, governed document, body path, profile position and source location.
- Reference occurrences must remain separate from BAE provenance.
- Reference occurrences must be stored only in the managed reference_occurrences field of the owning BAE record.
- A registered materializer must replace the complete managed occurrence projection before the blocking repository checks.
- The materializer must not create a BAE record from an unknown citation.
- The materializer must not modify BAE identity, title, base type, meaning, lifecycle state, origin, authoritative source, source history, provenance or relations.
- Repeated materialization of unchanged governed bodies must produce byte-equivalent registry content.
- The BAE validator must independently derive the occurrence projection and compare it with the materialized registry field.
- An active BAE must resolve one current authoritative source applicable to the current governed model.
- A non-active authoritative source must produce an explicit continuity, supersession or deprecation outcome.
- A source lifecycle change must identify every affected BAE and dependent governed document.
- Source continuity resolution must not infer historical origin from the first textual occurrence.
- Validation and occurrence derivation must remain side-effect-free.

## Scope

- Includes: manual canonical BAE registration
- Includes: governed-document BAE origins
- Includes: reviewed analytical addition origins
- Includes: current authoritative BAE sources
- Includes: append-only source history
- Includes: natural canonical BAE citations in profile-declared reference positions
- Includes: deterministic repository-wide reference occurrence derivation
- Includes: managed per-BAE reference_occurrences materialization
- Includes: pre-gate materialization and idempotence checks
- Includes: document lifecycle changes
- Includes: BAE lifecycle outcomes
- Excludes: automatic BAE creation from documentation
- Excludes: automatic source-history mutation
- Excludes: textual occurrence as semantic origin
- Excludes: reference occurrences persisted as provenance
- Excludes: editor-specific rendering
- Excludes: runtime database storage
- Excludes: methodology-overlay findings

## Acceptance

- The requirement is accepted when a citation of an unregistered BAE is rejected and does not create a registry record.
- The requirement is accepted when a registered BAE can be introduced through an ordinary canonical citation in its declared origin document.
- The requirement is accepted when the introductory citation is included in reference_occurrences.
- The requirement is accepted when every canonical BAE usage in a profile-declared reference position appears in the managed occurrence projection.
- The requirement is accepted when removing or moving a citation causes materialization to update its stored occurrence deterministically.
- The requirement is accepted when a stale materialized projection is rejected by check mode.
- The requirement is accepted when two write passes over unchanged documentation produce byte-equivalent registry content.
- The requirement is accepted when materialization leaves every manually governed BAE field unchanged.
- The requirement is accepted when the historical origin remains unchanged after an authority transfer.
- The requirement is accepted when the current authoritative source resolves from the terminal source-history entry.
- The requirement is accepted when a governed-document origin contains its eligible introductory citation.
- The requirement is accepted when a missing introductory citation in the declared origin body is rejected.
- The requirement is accepted when provenance and reference occurrence projections remain distinguishable.
- The requirement is accepted when an active BAE with a non-active authoritative source and no lifecycle outcome is rejected.
- The requirement is accepted when source-history cycles and discontinuities are rejected.
