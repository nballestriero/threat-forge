# MR-0003ADR-0001REQ-0006GOV-0001 — Deterministic Base DFD projection validation

## Intent

Ensure that Base DFD projections remain complete, traceable, reproducible, renderer-neutral and consistent with their canonical BAE sources.

## Governance obligation

- The Base DFD projection contract must define required collections for nodes, flows, boundaries and unprojected BAEs.
- The Base DFD projection contract must define stable identities for projected elements.
- The Base DFD projection contract must define controlled DFD role values.
- The Base DFD projection contract must define controlled unprojected reason identifiers.
- The Base DFD projection validator must publish stable rule identifiers.
- The Base DFD projection validator must reject an unknown top-level projection member.
- The Base DFD projection validator must reject a missing required top-level projection member.
- The Base DFD projection validator must reject a duplicate projected element identity.
- The Base DFD projection validator must reject an unknown DFD role.
- The Base DFD projection validator must reject an unresolved contributing BAE identity.
- The Base DFD projection validator must reject an unresolved contributing relation identity.
- The Base DFD projection validator must reject an Actor BAE projected with a role other than external entity.
- The Base DFD projection validator must reject a Component BAE projected with a role other than process.
- The Base DFD projection validator must reject a Boundary BAE omitted from the explicit boundary projection.
- The Base DFD projection validator must reject a projected Data Flow whose endpoints diverge from canonical endpoint relations.
- The Base DFD projection validator must reject a projected Data Flow that omits a canonical crossed Boundary relation.
- The Base DFD projection validator must reject an active BAE absent from both projected and unprojected collections.
- The Base DFD projection validator must reject an inactive BAE that contributes to the projection.
- The Base DFD projection validator must reject an unprojected BAE without a controlled reason identifier.
- The Base DFD projection validator must reject renderer-specific layout or presentation data.
- The Base DFD projection process must produce deterministic collection ordering.
- The Base DFD projection validation process must remain side-effect-free.
- The Base DFD projection verification suite must contain positive and negative fixtures.
- The implementation trace must link the projection contract, projector, validator and fixtures to this Governance Requirement.

## Verification obligations

- The verification must validate an empty active BAE inventory.
- The verification must validate the canonical projection of Actor, Component, Boundary and Data Flow BAEs.
- The verification must confirm that a Data Resource without a deterministic DFD role remains explicitly unprojected.
- The verification must confirm that every projected element retains all contributing BAE and relation identities.
- The verification must confirm that every active BAE appears in either a projected or unprojected collection.
- The verification must confirm that inactive BAEs do not contribute to the projection.
- The verification must compare repeated projection results for deterministic equivalence.
- The verification must confirm that projection and validation leave canonical BAE sources unchanged.
- The verification must cover unknown and missing top-level projection members.
- The verification must cover duplicate projected identities and unknown DFD roles.
- The verification must cover unresolved BAE and relation trace references.
- The verification must cover invalid Actor, Component and Boundary mappings.
- The verification must cover Data Flow endpoint divergence.
- The verification must cover omitted crossed Boundary relations.
- The verification must cover active BAEs omitted from both projected and unprojected collections.
- The verification must cover inactive BAEs included in the projection.
- The verification must cover missing and unknown unprojected reason identifiers.
- The verification must cover renderer-specific coordinates and presentation fields.
- The verification must project BAE-0001 as an external entity and BAE-0002 as a process.
- The verification must project BAE-0005 from BAE-0001 to BAE-0002 crossing BAE-0004.
- The verification must report BAE-0003 as unprojected with the controlled no-role reason.

## Failure conditions

- The verification must fail when a required projection collection is absent.
- The verification must fail when an unknown projection member, DFD role or unprojected reason is present.
- The verification must fail when a projected element identity is duplicated.
- The verification must fail when a contributing BAE or relation identity does not resolve.
- The verification must fail when a canonical BAE type is projected with an invalid DFD role.
- The verification must fail when a projected Data Flow diverges from its canonical endpoints or crossed Boundaries.
- The verification must fail when an active BAE is absent from both projected and unprojected collections.
- The verification must fail when an inactive BAE contributes to the projection.
- The verification must fail when renderer-specific layout or presentation data appears in the semantic projection.
- The verification must fail when identical canonical inputs produce different semantic output or ordering.
- The verification must fail when projection or validation modifies a canonical BAE source.
- The verification must fail when projection contract, projector, validator or fixture traceability is missing.
