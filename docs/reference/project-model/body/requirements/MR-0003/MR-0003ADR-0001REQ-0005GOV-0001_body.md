# MR-0003ADR-0001REQ-0005GOV-0001 — Deterministic BAE registry validation and negative coverage

## Intent

Ensure that persisted BAE sources and their reference projection remain complete, unique, resolvable and reproducible.

## Governance obligation

- The BAE registry validator must publish stable rule identifiers.
- The BAE registry validator must validate both canonical BAE registry paths.
- The BAE registry validator must reject an unknown top-level registry member.
- The BAE registry validator must reject a missing required top-level registry member.
- The BAE registry validator must reject a duplicate BAE identifier.
- The BAE registry validator must reject an invalid BAE identifier format.
- The BAE registry validator must reject an unknown base type.
- The BAE registry validator must reject an unknown lifecycle state.
- The BAE registry validator must reject an unknown origin kind.
- The BAE registry validator must reject a missing reviewed-addition evidence identifier.
- The BAE registry validator must reject an unresolved origin source.
- The BAE registry validator must reject an unresolved provenance source.
- The BAE registry validator must reject a missing origin provenance entry.
- The BAE registry validator must reject multiple origin provenance entries.
- The BAE registry validator must reject divergence between origin and origin provenance.
- The BAE registry validator must reject a duplicate relation identifier.
- The BAE registry validator must reject an invalid relation identifier format.
- The BAE registry validator must reject an unknown relation endpoint.
- The BAE registry validator must reject an unknown relation predicate.
- The BAE registry validator must reject an endpoint type that violates the predicate contract.
- The BAE registry validator must reject a Data Flow without one source endpoint.
- The BAE registry validator must reject a Data Flow without one target endpoint.
- The BAE registry validator must reject multiple source endpoints for one Data Flow.
- The BAE registry validator must reject multiple target endpoints for one Data Flow.
- The BAE reference-source projection validator must compare projected entries with canonical BAE records.
- The BAE reference-source projection validator must reject a stale or divergent projection.
- The BAE reference-source projection validator must confirm deterministic ordering.
- The BAE registry validation process must remain side-effect-free.
- The BAE registry verification suite must contain positive and negative fixtures.
- The implementation trace must link the validator and fixtures to this Governance Requirement.

## Verification obligations

- The verification must validate an empty canonical inventory.
- The verification must validate one complete record for every canonical base type.
- The verification must validate every controlled lifecycle state.
- The verification must validate both controlled origin kinds.
- The verification must validate every controlled relation predicate.
- The verification must compare projected records with their canonical element records.
- The verification must compare repeated projection results for deterministic equivalence.
- The verification must confirm that validation and projection leave canonical sources unchanged.
- The verification must cover duplicate and malformed BAE identifiers.
- The verification must cover unknown type, lifecycle, origin and relation values.
- The verification must cover missing, unresolved and divergent provenance.
- The verification must cover missing review evidence for analytical additions.
- The verification must cover duplicate and malformed relation identifiers.
- The verification must cover unknown endpoints and invalid endpoint types.
- The verification must cover missing and multiple Data Flow endpoints.
- The verification must cover stale and divergent projection output.

## Failure conditions

- The verification must fail when either canonical BAE registry path is missing.
- The verification must fail when a required registry member is absent.
- The verification must fail when a BAE identifier is duplicate or malformed.
- The verification must fail when a controlled BAE value does not resolve.
- The verification must fail when origin or provenance evidence does not resolve.
- The verification must fail when origin and origin provenance identify different sources.
- The verification must fail when a relation identifier is duplicate or malformed.
- The verification must fail when a relation endpoint or predicate does not resolve.
- The verification must fail when relation endpoint types violate the predicate contract.
- The verification must fail when a Data Flow lacks exactly one source endpoint.
- The verification must fail when a Data Flow lacks exactly one target endpoint.
- The verification must fail when projection differs from the canonical BAE sources.
- The verification must fail when identical inputs produce different projection ordering.
- The verification must fail when validation or projection modifies a canonical source.
- The verification must fail when validator or fixture traceability is missing.
