# MR-0003ADR-0001REQ-0006 — Deterministic Base Analysis DFD projection

## Intent

Derive a methodology-neutral and renderer-consumable DFD semantic projection directly from canonical Base Analysis Elements and their governed relations.

## Functional obligation

- ThreatForge must derive the Base DFD projection only from active canonical BAE records and canonical BAE relations.
- The Base DFD projection must map Actor BAEs to external entity nodes.
- The Base DFD projection must map Component BAEs to process nodes.
- The Base DFD projection must map Boundary BAEs to explicit boundaries.
- A Data Flow BAE must resolve its directed source and target from canonical endpoint relations.
- The Base DFD projection must associate Data Flow BAEs with every Boundary identified by canonical crossing relations.
- A Data Resource BAE must remain unprojected unless canonical relations or controlled refinements provide a deterministic DFD role.
- The projection must not infer DFD semantics from free-text BAE meaning fields.
- Each projected DFD element must retain traceability to every canonical BAE and relation that contributes to it.
- Each active BAE without a deterministic DFD role must appear in an explicit unprojected collection with a stable reason.
- Identical canonical BAE inputs must produce identical Base DFD semantic output.
- The Base DFD projection must remain independent from renderer-specific layout and presentation data.
- A rendering adapter must consume the Base DFD projection without applying independent BAE interpretation rules.

## Scope

- Includes: methodology-neutral Base DFD semantic projection
- Includes: Actor to external entity projection
- Includes: Component to process projection
- Includes: Boundary projection
- Includes: directed Data Flow endpoint resolution
- Includes: crossed Boundary resolution
- Includes: explicit unprojected BAE records
- Includes: traceability to canonical BAE and relation identities
- Includes: deterministic renderer-consumable output
- Excludes: STRIDE-specific projection rules
- Excludes: STRIDE-AI-specific projection rules
- Excludes: inference of DFD roles from free-text meanings
- Excludes: diagram coordinates and presentation styles
- Excludes: interactive DFD editing
- Excludes: detailed DFD levels

## Acceptance

- The requirement is accepted when only active canonical BAE records and canonical BAE relations contribute to the Base DFD projection.
- The requirement is accepted when Actor BAEs are represented as external entity nodes.
- The requirement is accepted when Component BAEs are represented as process nodes.
- The requirement is accepted when Boundary BAEs are represented as explicit boundaries.
- The requirement is accepted when every projected Data Flow resolves its canonical source endpoint and target endpoint.
- The requirement is accepted when every canonical crossed Boundary relation is represented by the projected Data Flow.
- The requirement is accepted when every projected DFD element resolves to every canonical BAE and relation that contributed to it.
- The requirement is accepted when every active BAE without a deterministic DFD role is reported explicitly with a stable reason.
- The requirement is accepted when repeated projection of identical canonical BAE inputs produces identical semantic output.
- The requirement is accepted when the projection contains no renderer-specific coordinates or presentation styles.
- The requirement is accepted when the documentation-to-base-analysis case study projects BAE-0001 as an external entity and BAE-0002 as a process.
- The requirement is accepted when the documentation-to-base-analysis case study projects BAE-0005 as a directed flow from BAE-0001 to BAE-0002 crossing BAE-0004.
- The requirement is accepted when the documentation-to-base-analysis case study reports BAE-0003 as unprojected because no deterministic DFD role is available.
