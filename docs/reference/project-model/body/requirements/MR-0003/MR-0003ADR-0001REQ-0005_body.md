# MR-0003ADR-0001REQ-0005 — Canonical BAE registry and reference-source projection

## Intent

Provide an authoritative persisted representation of Base Analysis Elements and a derived projection consumable by governed reference resolution and authoring assistance.

## Functional obligation

- The canonical BAE inventory must be stored at `docs/reference/project-model/registers/base-analysis/base-analysis-elements.registry.yml`.
- The canonical BAE taxonomy catalog must be stored at `docs/reference/project-model/registers/base-analysis/base-analysis-taxonomies.registry.yml`.
- The BAE inventory registry must declare `schema_version`, `registry_id`, `macro_requirement_id`, `elements` and `relations`.
- The BAE inventory `registry_id` must equal `base-analysis-elements-registry`.
- The BAE inventory `macro_requirement_id` must equal `MR-0003`.
- The BAE taxonomy `registry_id` must equal `base-analysis-taxonomies-registry`.
- The BAE taxonomy `macro_requirement_id` must equal `MR-0003`.
- Each BAE element record must declare `id`, `title`, `base_type`, `meaning`, `lifecycle_state`, `origin` and `provenance`.
- Each BAE identifier must match `BAE-[0-9]{4}`.
- A BAE identifier must remain unique within one analyzed project.
- The `base_type` member must reference a controlled value in the BAE taxonomy catalog.
- The controlled BAE base types must be `actor`, `component`, `data_resource`, `boundary` and `data_flow`.
- The `lifecycle_state` member must reference a controlled value in the BAE taxonomy catalog.
- The controlled BAE lifecycle states must be `active`, `superseded` and `deprecated`.
- Each controlled BAE value must declare a canonical label and explicit meaning.
- The `origin` member must declare `kind`, `source_id` and `source_path`.
- The controlled BAE origin kinds must be `governed_document` and `reviewed_analytical_addition`.
- A reviewed analytical addition origin must declare `review_evidence_id`.
- Each provenance entry must declare `relation`, `source_kind`, `source_id` and `source_path`.
- The controlled provenance relations must be `origin` and `support`.
- Each BAE record must contain exactly one provenance entry with relation `origin`.
- The origin provenance entry must identify the same source as the BAE `origin` member.
- Each BAE relation record must declare `id`, `source_bae_id`, `predicate` and `target_bae_id`.
- Each BAE relation identifier must match `BAE-REL-[0-9]{4}`.
- Each BAE relation predicate must reference a controlled predicate in the BAE taxonomy catalog.
- The BAE relation taxonomy must declare allowed source and target base types for every predicate.
- The BAE relation taxonomy must include `has_source_endpoint`, `has_target_endpoint` and `crosses_boundary`.
- A relation using `has_source_endpoint` must use a `data_flow` BAE as its source.
- A relation using `has_target_endpoint` must use a `data_flow` BAE as its source.
- A relation using `crosses_boundary` must use a `data_flow` BAE as its source.
- A relation using `crosses_boundary` must use a `boundary` BAE as its target.
- The BAE reference-source projection must be derived from the canonical BAE inventory and taxonomy catalog.
- Each projected BAE must expose `id`, `title`, `entity_type`, `base_type`, `meaning`, `lifecycle_state`, `origin`, `provenance` and `registry_path`.
- The projected `entity_type` must equal `base_analysis_element`.
- The BAE reference-source projection must preserve every canonical identifier and title.
- The BAE reference-source projection must order entries by canonical BAE identifier.
- The BAE reference-source projection must expose lifecycle and provenance data required by MR-0001 resolution and MR-0002 assistance.
- The BAE reference-source projection must not become an independent authoritative source.
- An empty canonical inventory must remain valid when `elements` and `relations` are empty lists.

## Scope

- Includes: canonical BAE inventory path
- Includes: BAE taxonomy catalog path
- Includes: element and relation record members
- Includes: identifier formats
- Includes: base-type, lifecycle, origin, provenance and relation taxonomies
- Includes: empty initial inventories
- Includes: deterministic reference-source projection
- Includes: ThreatForge and governed child-project inventories
- Excludes: concrete BAE records for the current project
- Excludes: overlay-specific threat and finding records
- Excludes: editor-specific ranking and rendering
- Excludes: runtime database storage
- Excludes: automatic acceptance of inferred elements

## Acceptance

- The requirement is accepted when an empty canonical BAE registry loads with empty `elements` and `relations` collections.
- The requirement is accepted when one complete BAE record resolves every required member and controlled value.
- The requirement is accepted when identifiers matching `BAE-[0-9]{4}` remain unique.
- The requirement is accepted when the taxonomy catalog exposes the five canonical base types and three lifecycle states.
- The requirement is accepted when a governed-document origin resolves its canonical source.
- The requirement is accepted when a reviewed analytical addition resolves its review evidence.
- The requirement is accepted when exactly one origin provenance entry matches the declared origin.
- The requirement is accepted when every relation resolves its endpoints and controlled predicate contract.
- The requirement is accepted when a Data Flow relation resolves source endpoint, target endpoint and optional Boundary crossings.
- The requirement is accepted when the reference-source projection preserves canonical identity, title and provenance.
- The requirement is accepted when repeated projection of identical sources produces equivalent ordered entries.
- The requirement is accepted when projection leaves both canonical registries unchanged.
