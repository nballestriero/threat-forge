# MR-0003ADR-0001REQ-0003 — Canonical BAE relations and system topology

## Intent

Represent methodology-neutral system structure through explicit relations among canonical Base Analysis Elements.

## Functional obligation

- The Base Analysis model must represent BAE relations as explicit governed records.
- Each BAE relation must identify one source BAE.
- Each BAE relation must identify one controlled predicate.
- Each BAE relation must identify one target BAE.
- Each BAE relation must preserve the canonical identities of both endpoints.
- The Base Analysis model must support relations among actors, components, data resources, boundaries and data flows.
- A Data Flow must identify its governed source endpoint.
- A Data Flow must identify its governed target endpoint.
- A Data Flow must expose every crossed Boundary relation.
- A topology projection must derive its nodes from the canonical BAE inventory.
- A topology projection must derive its edges from canonical BAE relations.
- An overlay relation must remain distinguishable from a methodology-neutral base relation.
- An overlay must not replace a canonical base relation silently.

## Scope

- Includes: methodology-neutral BAE relations
- Includes: Data Flow endpoints
- Includes: Boundary crossings
- Includes: topology projections
- Includes: overlay relation separation
- Excludes: STRIDE threat categories
- Excludes: diagram layout coordinates
- Excludes: editor-specific graph presentation

## Acceptance

- The requirement is accepted when every relation resolves a source BAE, controlled predicate and target BAE.
- The requirement is accepted when every Data Flow resolves its source and target endpoints.
- The requirement is accepted when Boundary crossings are available as explicit relations.
- The requirement is accepted when a topology projection contains only registered BAE identities.
- The requirement is accepted when overlay relations remain distinguishable from base relations.
