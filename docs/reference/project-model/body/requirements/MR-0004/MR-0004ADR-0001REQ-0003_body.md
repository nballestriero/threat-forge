# MR-0004ADR-0001REQ-0003 — Verifica documentale del progetto target tramite target_root

## Intent

Enable ThreatForge to validate the governed documentation and Base Analysis structure of one Target Project independently from the canonical ThreatForge workspace.

## Functional obligation

- The Target Project verification capability must receive one explicit target root for each verification request.
- The Target Project verification capability must apply the engine-owned canonical Macro-requirement, Decision, Functional Requirement and Governance Requirement model profiles to target-local registries and bodies.
- The Target Project verification capability must apply the engine-owned canonical Base Analysis inventory, taxonomy, provenance, relation and governed-reference rules to target-local Base Analysis records.
- The Target Project verification capability must validate target-local cross-model ownership and relation coherence.
- The Target Project verification capability must execute only checks applicable to Target Project documentation and Base Analysis.
- The Target Project verification capability must exclude ThreatForge development checks for implementation planning, scaffolding, promotion, repository commit-push and editor-extension packaging.
- The Target Project verification capability must write deterministic verification reports under the verified target root.
- The Target Project verification capability must keep target records, counts, diagnostics and reports separate from the canonical ThreatForge workspace.
- Target Project verification in check mode must not modify target-authored sources or canonical ThreatForge project-model sources.

## Scope

- Includes: explicit target-root input
- Includes: canonical governed-document profiles owned by the ThreatForge engine
- Includes: target-local Macro-requirement, Decision and Requirement registries and bodies
- Includes: optional target-local Governance Requirement records
- Includes: target-local cross-model coherence
- Includes: target-local Base Analysis inventory and taxonomy validation
- Includes: target-local BAE provenance, relations and governed references
- Includes: deterministic target-local reports
- Excludes: ThreatForge implementation planner checks
- Excludes: ThreatForge implementation scaffolder and promotion checks
- Excludes: ThreatForge governed repository commit-push checks
- Excludes: VS Code extension packaging checks
- Excludes: executable application code as a validation prerequisite
- Excludes: automatic extraction or acceptance of BAE candidates
- Excludes: modification of canonical ThreatForge counts or reports

## Acceptance

- The requirement is accepted when a document-only Target Project with canonical registries and bodies passes the applicable target checks.
- The requirement is accepted when a malformed target-local registry is rejected by the same canonical model rule used for the equivalent ThreatForge registry.
- The requirement is accepted when a malformed target-local governed Markdown body is rejected by the same canonical body-profile rule used for ThreatForge documentation.
- The requirement is accepted when an empty canonical target-local BAE inventory remains valid.
- The requirement is accepted when an invalid target-local BAE identity, type, origin, provenance or relation is rejected.
- The requirement is accepted when target verification reports identify only records belonging to the selected target root.
- The requirement is accepted when repeated check-mode verification of unchanged target sources produces equivalent diagnostics and leaves both target and ThreatForge authored sources unchanged.
