# MR-0004ADR-0001REQ-0005 — Workspace VS Code governato e assistenza BAE del progetto target

## Intent

Make one Target Project independently usable as a governed VS Code workspace while reusing ThreatForge-owned authoring, validation and Markdown reference assistance against target-local documents and Base Analysis records.

## Functional obligation

- The Target Project workspace capability must receive one explicit engine root and one explicit target root when its VS Code adapter is materialized.
- The Target Project workspace capability must materialize its editor configuration only beneath the selected target root.
- The materialized workspace must expose target-local preview, create and validation tasks that invoke engine-owned capabilities with the selected target root.
- The materialized workspace must keep canonical authoring rules, document profiles, controlled values and Markdown analysis logic owned by the ThreatForge engine.
- The materialized workspace must associate target-local authoring request files with an engine-derived governed document authoring schema.
- The materialized workspace must enable governed Markdown assistance for target-local bodies of every active engine-supported governed document model with complete assistance provider coverage.
- Governed Markdown assistance must resolve eligible Base Analysis Element references from the target-local canonical Base Analysis inventory.
- Governed Markdown assistance must offer canonical BAE identifier and title completions only in reference positions declared by the applicable engine-owned body profile.
- Governed Markdown assistance must report an error when a declared BAE reference identifies no target-local canonical element.
- Governed Markdown assistance must report canonical-title divergence and offer a non-destructive quick fix.
- Governed Markdown assistance must expose target-local BAE type, meaning, lifecycle, origin and provenance through hover information.
- Governed Markdown assistance must reject target-local BAE references that are structurally recognized but ineligible for the current document position.
- The Target Project workspace capability must not offer or resolve a canonical ThreatForge BAE that is absent from the target-local inventory.
- The Target Project workspace capability must preserve an empty target-local BAE inventory as valid and return no BAE completions.
- Repeated adapter materialization for unchanged engine and target inputs must produce equivalent target-local workspace files.
- Adapter materialization and editor assistance must not modify target-authored documents, target-local canonical BAE records or canonical ThreatForge project-model sources.

## Scope

- Includes: target-local VS Code settings
- Includes: target-local VS Code tasks
- Includes: target-local recommended extensions
- Includes: target-local schema projection
- Includes: target-local preview and create task wiring
- Includes: target-local document validation task wiring
- Includes: governed Markdown diagnostics
- Includes: governed Markdown completions
- Includes: canonical-title quick fixes
- Includes: BAE hover information
- Includes: target-local BAE inventory isolation
- Includes: deterministic adapter materialization
- Excludes: duplication of ThreatForge validation or Markdown analysis rules
- Excludes: BAE candidate extraction
- Excludes: BAE candidate review
- Excludes: canonical BAE materialization from candidates
- Excludes: web editor behavior
- Excludes: modification of target-authored Markdown during live analysis
- Excludes: automatic acceptance of editor suggestions
- Excludes: repository commit or push
- Excludes: references to canonical ThreatForge BAE records absent from the target inventory

## Acceptance

- The requirement is accepted when opening the generated target root as a VS Code workspace exposes target-local preview, create and validation tasks.
- The requirement is accepted when a target-local authoring request receives schema completion and validation derived from the engine-owned authoring contract.
- The requirement is accepted when typing a governed reference prefix in a declared target-local Markdown position offers the canonical identifier and title of an eligible BAE stored in the target inventory.
- The requirement is accepted when referencing an unknown target-local BAE identifier produces an editor error.
- The requirement is accepted when referencing an existing target-local BAE with a divergent title produces an editor error and a canonical-title quick fix.
- The requirement is accepted when hovering an existing target-local BAE reference displays its target-local type, meaning, lifecycle, origin and provenance.
- The requirement is accepted when a BAE present only in the canonical ThreatForge inventory is neither suggested nor resolved in the target workspace.
- The requirement is accepted when an empty valid target-local BAE inventory produces no completions and no workspace failure.
- The requirement is accepted when repeated adapter materialization with unchanged inputs produces no semantic workspace-file changes.
- The requirement is accepted when live assistance and adapter materialization leave target-authored documents, target-local BAE records and canonical ThreatForge sources unchanged.
