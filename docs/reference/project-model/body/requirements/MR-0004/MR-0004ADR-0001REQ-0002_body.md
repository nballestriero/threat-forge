# MR-0004ADR-0001REQ-0002 — Struttura documentale analizzabile del progetto target

## Intent

Enable a target project to represent a system through governed documentation alone so that ThreatForge can derive a methodology-neutral Base Analysis before executable application code exists.

## Functional obligation

- The target project template must create one project-local governed documentation root for Macro-requirement, Decision, Functional Requirement and Base Analysis records.
- The target project model must remain valid without executable source code, a running backend, a frontend or a database instance.
- The target project documentation must provide authoritative project-local sources for actors, logical components, data resources, trust boundaries and information flows.
- The target project model must preserve stable project-local identifiers and source paths for governed documents and Base Analysis records.
- The target project model must support documentary provenance from each Base Analysis Element to one or more project-local governed sources.
- The target project documentation must remain isolated from the canonical ThreatForge project model.

## Scope

- Includes: project-local Macro-requirement, Decision and Functional Requirement registries and bodies
- Includes: project-local Base Analysis inventory and provenance records
- Includes: documentary descriptions of actors and logical components
- Includes: documentary descriptions of data resources and trust boundaries
- Includes: documentary descriptions of information flows
- Includes: analysis before implementation artifacts exist
- Excludes: executable application source code
- Excludes: a running backend or frontend
- Excludes: a real database instance
- Excludes: implementation trace records as a prerequisite for Base Analysis
- Excludes: automatic acceptance of inferred Base Analysis Elements without governed review
- Excludes: modification of the canonical ThreatForge project model

## Acceptance

- The requirement is accepted when a generated target project passes its structural validation without containing executable source code.
- The requirement is accepted when the target project can contain at least one Macro-requirement, one Decision and one Functional Requirement as governed project-local sources.
- The requirement is accepted when the target documentation can identify an actor, a logical component, a data resource, a trust boundary and an information flow without relying on implementation artifacts.
- The requirement is accepted when a Base Analysis Element can identify its governed origin and supporting source occurrence inside the target project.
- The requirement is accepted when creating and documenting the target project leaves the canonical ThreatForge project-model files unchanged.
