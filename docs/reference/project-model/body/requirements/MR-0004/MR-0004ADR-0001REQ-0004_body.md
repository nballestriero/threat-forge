# MR-0004ADR-0001REQ-0004 — Authoring governato del progetto target tramite target_root

## Intent

Enable ThreatForge to preview and create governed project-model documents inside one explicitly selected Target Project while preserving engine-owned rules and target-owned content.

## Functional obligation

- The Target Project authoring capability must receive one explicit target root for every preview or create request.
- The Target Project authoring capability must resolve the selected target root independently from the ThreatForge engine root.
- The Target Project authoring capability must use engine-owned document catalogs, logical models, body profiles, controlled values, authoring provider coverage and validation rules.
- The Target Project authoring capability must derive its active authorable document inventory from the engine-owned canonical catalog.
- The Target Project authoring capability must read existing Macro-requirement, Decision and Requirement ownership data from the selected target root.
- The Target Project authoring capability must derive registry and Markdown body paths relative to the selected target root.
- The Target Project authoring capability must allocate document identifiers from the existing target-local ownership scope.
- Preview mode must report the exact target-local artifacts and content that creation would produce without modifying either root.
- Create mode must write only the planned target-local registry and Markdown body changes.
- Create mode must validate the target-local governed document corpus before finalizing the transaction.
- Create mode must roll back all target-local authored changes when validation fails.
- The Target Project authoring capability must reject a target root that is missing its required project-model ownership structure.
- The Target Project authoring capability must reject any planned path that escapes the selected target root.
- The Target Project authoring capability must preserve canonical ThreatForge project-model sources, counts and reports unchanged.
- Repeated preview of an unchanged request and target corpus must produce equivalent plans.

## Scope

- Includes: explicit engine-root and target-root separation
- Includes: target-local authoring for every active governed document model with complete engine-owned authoring provider coverage
- Includes: engine-owned authoring catalogs and validation rules
- Includes: deterministic preview
- Includes: transactional target-local creation
- Includes: rollback on failed target validation
- Includes: target-local identifier allocation
- Excludes: VS Code task and schema materialization
- Excludes: BAE candidate extraction
- Excludes: BAE candidate review and canonical materialization
- Excludes: automatic project migration
- Excludes: authoring outside the selected target root
- Excludes: modification of canonical ThreatForge project-model sources
- Excludes: repository commit or push of the target project

## Acceptance

- The requirement is accepted when previewing one target-local document request reports only paths beneath the selected target root.
- The requirement is accepted when creating one valid request updates the correct target-local registry and creates the correct target-local Markdown body.
- The requirement is accepted when target-local identifier allocation remains independent from identifiers used by canonical ThreatForge documents.
- The requirement is accepted when an invalid target corpus prevents finalization and restores the target to its pre-request authored state.
- The requirement is accepted when a path-escape attempt is rejected before any target or engine file is modified.
- The requirement is accepted when preview and create leave canonical ThreatForge project-model sources, counts and reports unchanged.
- The requirement is accepted when repeated previews of unchanged inputs produce equivalent plans.
