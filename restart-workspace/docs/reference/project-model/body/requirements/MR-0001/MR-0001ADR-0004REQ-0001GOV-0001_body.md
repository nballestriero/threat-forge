# MR-0001ADR-0004REQ-0001GOV-0001 — Coerenza deterministica dei valori tassonomici documentali

## Intento

I valori controllati non devono essere stringhe libere o sinonimi impliciti.

## Obbligo di governance

Ogni valore controllato usato dai registri coperti dal modello tassonomico deve essere presente nel value set applicabile e deve avere un significato esplicito.

I value set devono essere contestuali. In particolare, il campo `status` non deve essere validato contro una lista globale unica, ma contro il value set specifico del registro e del tipo di record in cui compare.

## Controlli minimi

Il controllo deve verificare almeno:

- unicità degli id dei value set;
- unicità dei nomi dei value set;
- presenza di `field_name`;
- presenza di `applies_to_registry`;
- presenza di `applies_to_record`;
- presenza di descrizione per ogni value set;
- presenza di significato per ogni valore ammesso;
- coerenza tra i ruoli delle label usati nel vocabolario e il value set `vocabulary_label_role`;
- coerenza tra gli status dei termini e il value set `vocabulary_term_status`;
- coerenza tra gli status dei check e il value set `check_status`;
- coerenza tra gli status degli artefatti implementativi e il value set `implementation_artifact_status`;
- coerenza tra gli status delle decisioni e il value set `decision_status`;
- coerenza tra gli status dei requirement e il value set `requirement_lifecycle_status`;
- assenza di frasi operative temporanee vietate nei documenti governati non dedicati alla loro dichiarazione.

## Esito atteso

Il controllo fallisce in presenza di valori non registrati nel value set applicabile, valori duplicati, ruoli non ammessi, status usati nel contesto sbagliato o frasi temporanee vietate nella documentazione governata.
