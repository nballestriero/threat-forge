# MR-0000REQ-0007GOV-0003 — Governed repository operation command anti-regression guard

## Intent

The governed repository operation runner and its npm entrypoints must not be removed, renamed, or disconnected from the gate sequence accidentally.

This specialized governance requirement protects the local path that runs deterministic gates before routine commits and pushes.

## Parent Functional Requirement

Parent functional requirement: `MR-0000REQ-0007` — Runner unico MR-0000 per i gate di coerenza del project model.

## Specialized Requirement

The system must provide a deterministic anti-regression guard that verifies the canonical governed repository operation commands and runner path remain present, correctly wired, and traceable.

The guard must fail when `repo:check`, `repo:commit-push`, or the governed repository operation runner path are removed or changed without updating the governed model.

## Scope

This requirement applies to the local project-model governance workflow under `MR-0000`.

It covers npm command availability, the expected runner file path, runner JSDoc traceability markers, required runner gate command references, and graph traceability for the anti-regression guard itself.

It does not define remote branch protection, replace server-side repository policy, prevent emergency manual Git recovery, or turn the runner into a general CI pipeline.

## Rules

- The root `package.json` must define `repo:check` as the check-only governed repository operation entrypoint.
- The root `package.json` must define `repo:commit-push` as the governed commit-push entrypoint.
- The governed repository operation runner file must exist at its canonical MR-0000 path.
- The runner must retain JSDoc traceability to `MR-0000REQ-0007GOV-0001`, `MR-0000REQ-0007GOV-0002`, `MR-0000/ADR-0003`, and `MR-0000`.
- The runner must continue to reference every required project-model gate command, including this anti-regression guard.
- The anti-regression guard itself must be available as an npm gate command and included in the governed runner sequence.
- The anti-regression guard implementation must include JSDoc traceability to this requirement.
- The graph must connect this requirement to the anti-regression guard implementation and verification artifact.

## Acceptance Criteria

```gherkin
Scenario: Canonical repository operation commands are present
  Given the repository uses the governed local commit-push path
  When the anti-regression guard runs
  Then it verifies that `repo:check` and `repo:commit-push` point to the canonical MR-0000 runner

Scenario: Runner path is present and traceable
  Given the canonical runner path is declared by the project model
  When the anti-regression guard runs
  Then it verifies that the runner file exists
  And that the runner still declares the expected JSDoc requirement, ADR, and macro-requirement traceability markers

Scenario: Runner gate sequence remains wired
  Given the governed runner orchestrates project-model gates
  When the anti-regression guard runs
  Then it verifies that the runner references every required gate command
  And includes the anti-regression guard gate itself

Scenario: A command is removed or changed
  Given `repo:check`, `repo:commit-push`, or the anti-regression guard gate is removed or changed
  When the anti-regression guard runs
  Then the command exits with a non-zero status
  And reports the missing or changed entrypoint
```

## Verification Expectation

Running `npm run docs:repo-operation-governance` and `npm run repo:check` must pass and must report this requirement as implemented.
