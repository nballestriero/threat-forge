# MR-0000REQ-0007GOV-0004 — Repository operation governance negative fixture coverage

## Intent

The governed repository operation guard must prove that representative invalid command, runner, and graph states fail closed instead of only passing on the current repository.

This specialized governance requirement protects the anti-regression guard from becoming a passive smoke test without failure-mode coverage.

## Parent Functional Requirement

Parent functional requirement: `MR-0000REQ-0007` — Runner unico MR-0000 per i gate di coerenza del project model.

## Specialized Requirement

The system must provide deterministic negative fixture coverage for the repository operation governance guard.

The fixtures must exercise invalid repository states where canonical `repo:*` commands, the governed runner, required runner gate references, or graph traceability fragments are removed or changed.

## Scope

This requirement applies to the local MR-0000 repository operation governance guard and its isolated fixture execution.

It covers fixture definitions, deterministic fixture execution, expected diagnostic matching, and summary reporting from `docs:repo-operation-governance`.

It does not define branch protection, remote repository policies, Git hook enforcement, or end-to-end push simulations.

## Rules

- The repository operation governance checker must execute negative fixtures from a governed fixture directory.
- Each fixture must run in an isolated temporary repository root.
- Each fixture must define the repository files needed to trigger one focused invalid state.
- Each fixture must fail the checker with a non-zero exit status.
- Each fixture must declare an expected diagnostic fragment and the checker must verify that the diagnostic is emitted.
- The checker must fail if a negative fixture unexpectedly passes.
- The checker must report the number of executed negative fixtures.

## Acceptance Criteria

```gherkin
Scenario: Removed canonical command is detected
  Given a fixture removes or changes a canonical `repo:*` script
  When `docs:repo-operation-governance` executes fixture coverage
  Then the fixture fails with an expected command diagnostic

Scenario: Missing runner path is detected
  Given a fixture omits the governed repository operation runner file
  When `docs:repo-operation-governance` executes fixture coverage
  Then the fixture fails with an expected missing-runner diagnostic

Scenario: Missing runner gate is detected
  Given a fixture removes a required gate command reference from the runner
  When `docs:repo-operation-governance` executes fixture coverage
  Then the fixture fails with an expected missing-gate diagnostic

Scenario: Missing graph traceability is detected
  Given a fixture omits required repository operation governance graph fragments
  When `docs:repo-operation-governance` executes fixture coverage
  Then the fixture fails with an expected graph-traceability diagnostic
```

## Verification Expectation

Running `npm run docs:repo-operation-governance` and `npm run repo:check` must pass and must report this requirement as implemented with the number of repository operation governance negative fixtures executed.
